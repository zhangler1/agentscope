# 01-快速开始 · BocomAgentScope 引擎层上手

> 本文用**引擎层（底层）**写法，带你用最短篇幅、几行代码构造一个智能体并直接对话。
> 引擎层关注「一个 Agent 怎么想、用什么模型、挂什么工具」，不封装存储 / 多租户 / HTTP 服务——适合快速实验、学原理、做单用户脚本。
> 若要落库、多用户、对外提供 HTTP 服务，请参阅 `03-智能体.md`、`07-工作区与沙箱.md` 及服务层（应用层）文档。

---

## 一、BocomAgentScope 引擎层是什么

BocomAgentScope 是一个构建智能体（Agent）的框架。在**引擎层**，你只需要关注一个核心对象：

```python
agent = Agent(
    name="...",
    system_prompt="...",
    model=model,
    toolkit=toolkit,
    middlewares=[...],
)
```

然后用 `await agent.reply(msg)`（或 `reply_stream` 流式）让它回答用户。框架替你处理好：模型调用、工具调用循环（ReAct）、中间件链。你只需专注「智能体怎么想、用什么模型、挂什么工具」。

对话有两种拿结果的方式：
- **`reply`**：整轮跑完返回完整结果（适合只要答案）。
- **`reply_stream`**：异步迭代，逐块收到文本增量、工具调用等事件（适合边生成边显示）。

## 二、安装

```bash
pip install bocomagentscope        # 框架本体（含 Agent / 模型 / 工具 / 中间件）
pip install bocomadp               # 本项目扩展：ELLM 模型与凭证、K8s 沙箱等（本示例用 ELLM，必装）
```

> 引擎层不强制依赖数据库 / Redis：模型走 OpenAI 兼容 HTTP，工具在本地执行后端运行。

## 三、五分钟跑通（完整代码）

把下面整段保存为 `main.py`，直接 `python main.py` 即可看到一次完整对话。

```python
# main.py
import asyncio
from bocomagentscope.agent import Agent
from bocomadp.providers.ellm_chat_model import EllmChatModel
from bocomadp.credential import ELLMCredential
from bocomagentscope.tool import Toolkit, Bash, Read, Write, Edit
from bocomagentscope.middleware import TracingMiddleware
from bocomagentscope.message import Msg

# 1) 模型：用本项目自研 ELLM（OpenAI 兼容网关）。
#    EllmChatModel 是 OpenAIChatModel 子类，专门对接 ELLM 协议；
#    凭证用 ELLMCredential（含 scene_code 场景码）。
model = EllmChatModel(
    credential=ELLMCredential(
        api_key="你的APIKey",                              # ELLM 通常不校验，任意值即可
        base_url="http://host.docker.internal:8001/v1",    # ELLM 的 OpenAI 兼容端点
        organization="your-org",                           # EllmChatModel 会读取，必须存在
        scene_code="你的场景码",                            # 场景编码（业务字段，原样存储）
    ),
    model="deepseek-v4-flash",                             # ELLM 提供的模型
    stream=True,
)

# 2) 工具：直接 new 内置工具，塞进 Toolkit
toolkit = Toolkit(tools=[Bash(), Read(), Write(), Edit()])

# 3) 构造智能体（引擎层核心写法）
agent = Agent(
    name="assistant",
    system_prompt="You are a helpful assistant.",
    model=model,
    toolkit=toolkit,
    middlewares=[TracingMiddleware()],                     # 横切逻辑（如链路追踪）由中间件实现
)


async def main():
    reply = await agent.reply(
        Msg(name="user", role="user", content="你好，用一句话介绍你自己"),
    )
    print(reply.content)


if __name__ == "__main__":
    asyncio.run(main())
```

运行：

```bash
python main.py
```

控制台打印智能体的回答。这是一个**基础智能体**：配置只含 `name` + `system_prompt` + `model`，工具由你在 `Toolkit` 里显式注入（上面注入了 `Bash/Read/Write/Edit`）。

## 四、拆开看：模型与凭证（ELLM 凭证）

```python
from bocomadp.providers.ellm_chat_model import EllmChatModel
from bocomadp.credential import ELLMCredential

model = EllmChatModel(
    credential=ELLMCredential(
        api_key="你的APIKey",                              # ELLM 通常不校验，任意值即可
        base_url="http://host.docker.internal:8001/v1",    # ELLM 的 OpenAI 兼容端点
        organization="your-org",                           # EllmChatModel 会读取，必须存在
        scene_code="你的场景码",                            # 场景编码（业务字段，原样存储）
    ),
    model="deepseek-v4-flash",                             # ELLM 提供的模型
    stream=True,
)
```

- `ELLMCredential` 是本项目自研 **ELLM** 的凭证（继承 `CredentialBase`），字段为 `api_key` / `base_url` / `organization` / `scene_code`。`organization` 必须存在，ELLM 网关会读取；`scene_code` 为业务场景编码。
- 模型用 **`EllmChatModel`**（来自 `bocomadp.providers.ellm_chat_model`），它是 `OpenAIChatModel` 的子类，专门对接 ELLM 网关（处理 `<think>` 标签注入、`max_tokens` 字段名等协议差异）。`model` 填 ELLM 候选模型，如 `deepseek-v4-flash`。
- `stream=True` 启用流式——配合 `reply_stream` 使用。
- 框架不内置任何默认模型 / 凭证，**必须显式构造 `model` 才能对话**。
- 注：`EllmChatModel` 会尝试从 Redis 读取模型上下文窗口（`bocomadp:model:think_tag`），Redis 不可用时自动降级为 65536，不阻塞运行。

## 五、拆开看：工具从哪来（引擎层由你显式注入）

> **关键认知**：引擎层**没有「工作区自动注入工具」这回事**（那是服务层 `workspace` 的能力）。在引擎层，工具就是你在 `Toolkit(tools=[...])` 里**显式 new 出来的对象**——你塞什么，智能体就有什么。

### 5.1 框架内置的工具类

以下都从 `bocomagentscope.tool` 直接导入、实例化即可：

| 类别 | 工具类 | 作用 |
| --- | --- | --- |
| 命令执行 | `Bash` / `PowerShell` | 执行 shell 命令（按运行平台二选一） |
| 文件 | `Read` / `Write` / `Edit` | 读 / 写 / 编辑文件 |
| 搜索 | `Glob` / `Grep` | 模式匹配路径 / 搜索文本 |
| 任务 | `TaskCreate` / `TaskGet` / `TaskList` / `TaskUpdate` | 任务拆解与跟踪 |
| 其他 | `ResetTools` | 复位工具状态 |
| 工具容器 | `Toolkit` | 把多个工具组合成一个 toolkit 传给 Agent |

示例（注入文件 + 搜索类工具）：

```python
from bocomagentscope.tool import Toolkit, Bash, Read, Write, Edit, Glob, Grep

toolkit = Toolkit(tools=[Bash(), Read(), Write(), Edit(), Glob(), Grep()])
agent = Agent(name="assistant", system_prompt="...", model=model, toolkit=toolkit)
```

### 5.2 自定义工具

引擎层自定义工具支持三种写法：把普通函数用 `FunctionTool` 包装（最常用）、继承 `ToolBase` 实现复杂工具（有状态 / 自定义安全检查）、或在引入业务侧工具扩展包后用其 `@tool` 装饰器。接入外部能力还可挂 MCP（STDIO / HTTP 长连接）。

> **请参考**：`03-工具-mcp-cli/使用工具指南.md` —— 含函数包装、ToolBase 子类、工具命名规范、内置工具安全分析、MCP 接入（StdioMCPConfig / HttpMCPConfig / MCPClient）与工具中间件的完整写法与示例。

### 5.3 查看外部 skill hub（服务层能力）

**技能（skill）由服务层 / 工作区提供，引擎层 `Agent` 不直接挂载**——skill 本质是由工作区加载、组织好的一组工具与提示。引擎层要复用某能力，直接把对应工具塞进 `Toolkit`（见 5.2）即可；若要**查看 / 安装外部 skill hub 上的技能**，需走服务层。

> **请参考**：`04-技能/使用技能指南.md` —— 含服务注册 `skill_hubs=[SkillHub()]` 后通过 `GET /api/workspace/skills/external` 浏览外部目录（前端 / curl 方式），以及用 `skill_hub_sdk.services` 的 `install_skills` / `uninstall_skills` 在代码中安装、删除的完整参数与作用域 / 对账语义说明。

## 六、拆开看：发起对话（reply 原生 vs reply_stream 流式）

```python
from bocomagentscope.message import Msg

# 原生：整轮跑完，返回完整回复
reply = await agent.reply(
    Msg(name="user", role="user", content="你好，用一句话介绍你自己"),
)
print(reply.content)

# 流式：异步迭代，逐块接收事件（文本增量、工具调用等）
async for chunk in agent.reply_stream(
    Msg(name="user", role="user", content="帮我列个计划"),
):
    # chunk 为流式事件对象，按需处理（如实时打印文本块）
    ...
```

两者底层是同一个 ReAct 引擎，区别只在「怎么拿结果」：

| | `reply` | `reply_stream` |
| --- | --- | --- |
| 结果获取 | 整轮跑完返回 `Msg` | `async for` 逐块收事件 |
| 是否实时 | 否，一次性拿最终答案 | 是，边生成边推送 |
| 适用场景 | 后台 / 批处理、只要答案 | 前端边生成边显示、或逐块记录 |

> 一句话：要「要答案」用 `reply`；想「看过程 / 边生成边显示」用 `reply_stream`。

## 七、进阶：中间件与状态

- **中间件（middlewares）**：横切逻辑（日志、审计、链路追踪、限流）通过 `middlewares=[...]` 注入，例如上文的 `TracingMiddleware`。更多见 `02-核心概念.md`。
- **状态（state）**：`Agent` 构造时可传 `state`，用于跨轮共享上下文 / 记忆；上下文窗口与 RAG 管理见 `05-上下文管理.md`。
- **结构化输出、计划模式、团队协作**：引擎层对应能力见 `03-智能体.md`、`06-工具.md`。
