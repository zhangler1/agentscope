# 01-快速开始 · BocomAgentScope 服务层（应用层）上手

> 本文用**服务层（应用层）**写法，带你用最短篇幅把一个智能体做成「可持久化、可对外 HTTP 服务」的应用：装配存储 / 消息总线 / 工作区 → 注册凭证 → 创建智能体 → 创建会话绑模型 → 导入工具 / 技能 → 驱动对话。
> 服务层关注「多用户、落库、HTTP 化」，底层仍是同一个 ReAct 引擎；若只想单文件脚本快速试跑，请见各引擎层参考文档。

---

## 一、服务层是什么

服务层把「一个智能体怎么跑」封装成可运维的产品形态。你需要关注的不是单个 `Agent` 对象，而是几个装配好的组件：

- `create_app(...)`：用存储、消息总线、工作区管理器组装应用，并挂载 chat / skill / mcp 等 HTTP 端点；
- `storage`：智能体 / 会话 / 状态 / 凭证落库（PG + Redis），按 `user` / `agent` / `session` 隔离；
- `workspace_manager`：运行时注入内置工具、本地技能目录、MCP；
- `chat_service.run(...)`：驱动一次对话，事件经 `message_bus` 持久化 + 实时推送。

驱动入口是 `await chat_service.run(user_id, session_id, agent_id, input_msg=)`，而非引擎层的 `agent.reply`。下文依次讲清每个组件。

## 三、五分钟跑通（完整代码）

把下面整段保存为 `main.py`，直接 `python main.py` 即可看到一次完整对话（落库 + 经工作区注入工具 / 模型）。

```python
# main.py
import asyncio
from bocomagentscope.app import create_app
from bocomagentscope.app.storage import (
    PostgresStorage, RedisMessageBus,
    AgentRecord, AgentData, SessionConfig, ChatModelConfig,
)
from bocomagentscope.app.workspace_manager import (
    LocalWorkspaceManager, IsolationPolicy,
)
from bocomagentscope.app.service import ChatService
from bocomagentscope.app.message_bus import MessageBusKeys
from bocomagentscope.mcp import MCPClient, StdioMCPConfig
from bocomadp.credential import ELLMCredential
from bocomagentscope.message import Msg

USER_ID = "u-demo"

async def main():
    # 1) 存储：智能体 / 会话 / 状态落库（PG + Redis）
    storage = await PostgresStorage.create(dsn="postgresql://user:pwd@pg:5432/db")
    message_bus = await RedisMessageBus.create(url="redis://redis:6379/0")

    # 2) 工作区 / 沙箱（本地调试）
    #    目录约定：
    #      ./data/workspaces/<workspace_id>/  智能体运行工作区（工具读写落在此）
    #      ./skills/<skill_name>/SKILL.md      本地技能目录（其下含 SKILL.md 的子目录）
    workspace_manager = LocalWorkspaceManager(
        basedir="./data/workspaces",
        isolation=IsolationPolicy.PER_SESSION,   # 按会话隔离；PER_AGENT=同智能体共享
        default_mcps=[                            # 可选：注入 MCP 工具（以文件系统为例）
            MCPClient(
                name="file_system",
                is_stateful=True,
                mcp_config=StdioMCPConfig(command="mcp-server-filesystem"),
            ),
        ],
        skill_paths=["./skills"],                 # 可选：加载本地技能目录
    )

    # 3) 组装应用（mcp_hubs / skill_hubs 用于接入「外部 Hub」，见 八 / 九）
    app = create_app(
        storage=storage,
        message_bus=message_bus,
        workspace_manager=workspace_manager,
        # mcp_hubs=[GitHubMCPHub()],   # 可选：接入外部 MCP Hub
        # skill_hubs=[SkillHub()],     # 可选：接入外部 Skill Hub
    )
    chat_service: ChatService = app.state.chat_service

    # 4) 创建 ELLM 凭证 → 拿到 credential_id（仅 scene_code 必填）
    credential_id = await storage.upsert_credential(
        USER_ID,
        ELLMCredential(
            scene_code="你的场景码",                            # 必填：业务场景编码（原样存储）
            # api_key="你的APIKey",                            # 可选：ELLM 动态刷新 key，通常留空
            # base_url="http://host.docker.internal:8001/v1",  # 可选：ELLM 的 OpenAI 兼容端点
            # organization="your-org",                         # 可选：组织 ID
        ),
    )

    # 5) 创建智能体（落库，而非内存对象）
    agent_id = await storage.upsert_agent(
        USER_ID,
        AgentRecord(
            user_id=USER_ID,
            data=AgentData(
                name="基础智能体",
                system_prompt="你是一个简洁的助手，回答不超过两句话。",
            ),
        ),
    )

    # 6) 创建会话并绑定模型（引用 credential_id）
    session_id = await storage.upsert_session(
        USER_ID,
        agent_id,
        SessionConfig(
            workspace_id="<由 workspace_manager 按隔离策略分配>",
            chat_model_config=ChatModelConfig(
                type="ellm_credential",        # 模型供应商类型（ELLM 取值以 examples/agent_service/main.py 的 setup_model 为准）
                credential_id=credential_id,   # 4) 返回的凭证 id
                model="deepseek-v4-flash",     # ELLM 候选模型（见 ELLMCredential 的 list_models）
                parameters={"temperature": 0.7},
            ),
        ),
    )

    # 7) 驱动对话并流式打印回复（订阅 message_bus 的会话事件流）
    #    先订阅本会话频道，再运行对话；run 期间的文本增量事件会实时推送过来。
    sub = message_bus.subscribe(MessageBusKeys.session_events(session_id))
    TEXT_BLOCK_DELTA = "TEXT_BLOCK_DELTA"

    async def _run():
        async with message_bus:                      # 持有会话锁
            await chat_service.run(
                user_id=USER_ID,
                session_id=session_id,
                agent_id=agent_id,
                input_msg=Msg(name="user", role="user",
                              content="你好，用一句话介绍你自己"),
            )

    async def _print():
        async for event in sub:                      # event 是 dict
            if event.get("type") != TEXT_BLOCK_DELTA:
                continue
            delta = event["data"].get("content") or event["data"].get("delta") or ""
            if delta:
                print(delta, end="", flush=True)     # 逐 token 打印回复增量
        print()                                      # run 结束、订阅关闭后收尾

    await asyncio.gather(_run(), _print())           # 运行与打印并发

if __name__ == "__main__":
    asyncio.run(main())
```

## 八、导入外部工具（MCP）

服务层注入工具有两种方式，**外部工具统一走 MCP**：

- **静态注入（四、已演示）**：在 `workspace_manager` 上配 `default_mcps=[MCPClient(...)]`，每个会话启动时自动挂载这些 MCP 工具（如文件系统、数据库等）。
- **外部 Hub 自动发现**：在 `create_app(mcp_hubs=[GitHubMCPHub()])` 注册 MCP Hub，运行时从 Hub 拉取可用 MCP 列表，前端可浏览并安装到指定智能体。

> MCP 工具的接入细节（StdioMCPConfig / HttpMCPConfig / `MCPClient` 构造、命名空间、按名筛选）见 `03-工具-mcp-cli/使用工具指南.md`。

## 九、导入外部 skill

技能同样分两种来源：

- **本地目录（四、已演示）**：在 `workspace_manager` 上配 `skill_paths=["./skills"]`，其下含 `SKILL.md` 的子目录会被 `LocalSkillLoader` 加载。
- **外部 Skill Hub**：在 `create_app(skill_hubs=[SkillHub()])` 注册 Hub 后，用 `skill_hub_sdk` 把 Hub 上的 skill 安装到某智能体的工作区：

```python
from skill_hub_sdk.services import install_skills   # 位于 examples/skill_hub_sdk

async def import_external_skill(agent_id: str, session_id: str):
    result = await install_skills(
        workspace_manager,                 # 四、的 workspace_manager
        user_id=USER_ID,
        agent_id=agent_id,
        session_id=session_id,
        skill_names=["global:write", "public:read"],  # 命名空间:技能名
        guwp_token="...",                              # 可选；不传仅能装公共 skill
        sync=True,                                     # 对账：删除工作区中多余 skill
    )
    # result: {"installed": [...], "removed": [...], "skipped": [...]}
    # 安装后落到智能体 workspace 目录，运行时随工作区注入
```

> 外部 hub 的浏览（前端 `GET /api/workspace/skills/external`）、安装/删除完整参数与作用域语义，见 `04-技能/使用技能指南.md`。

## 十一、流式打印回复内容（代码内订阅消息总线）

服务层不一定要走 HTTP 才能拿流式输出——对话运行期间，每个事件都会经 `message_bus` 实时发布到该会话的频道。直接在代码里**订阅会话事件流**，过滤出文本增量事件（`TEXT_BLOCK_DELTA`），即可逐 token 打印回复正文，无需任何 API / SSE 客户端。

### 11.1 先启动对话（后台跑），再订阅事件流

`chat_service.run` 是 `async with` 块（运行期间持有会话锁）。把"运行对话"和"订阅打印"放进同一个 `async with message_bus`，在 `run` 启动**前**先订阅，`run` 运行期间即可实时收到增量：

```python
# stream_print.py —— 接四~十节的 storage / message_bus / chat_service / session_id
import asyncio
from bocomagentscope.app.message_bus import MessageBusKeys
from bocomagentscope.message import Msg

TEXT_BLOCK_DELTA = "TEXT_BLOCK_DELTA"   # 文本增量事件类型名


async def chat_and_stream(agent_id: str, session_id: str):
    # 1) 订阅本会话的事件流（返回异步迭代器，逐条 yield dict 事件）
    sub = message_bus.subscribe(MessageBusKeys.session_events(session_id))

    # 2) 在订阅已建立后，启动对话（run 期间持续发布事件）
    async def _run():
        async with message_bus:                      # 持有会话锁
            await chat_service.run(
                user_id=USER_ID,
                session_id=session_id,
                agent_id=agent_id,
                input_msg=Msg(name="user", role="user",
                              content="你好，用一句话介绍你自己"),
            )

    async def _print():
        # 3) 只挑文本增量事件，逐 token 打印
        async for event in sub:
            # event 是 dict，形如 {"type": "TEXT_BLOCK_DELTA", "data": {...}, ...}
            if event.get("type") != TEXT_BLOCK_DELTA:
                continue
            delta = event["data"].get("content") or event["data"].get("delta") or ""
            if delta:
                print(delta, end="", flush=True)
        print()   # run 结束、订阅关闭后收尾换行

    # 并发：打印协程与对话协程同时进行，互不打断
    await asyncio.gather(_run(), _print())
```

要点：

- **事件即 dict**：订阅 `MessageBusKeys.session_events(session_id)` 拿到的是 `dict`（不是对象），用 `event["type"]` 区分类型，`event["data"]` 取载荷。
- **正文增量在 `TEXT_BLOCK_DELTA`**：模型每吐出一小段，就会发一个该类型事件，`data` 里的文本字段是 `content`（个别版本写作 `delta`），取非空值即为流式回复增量。
- **订阅时机**：必须在 `chat_service.run` 之前（或 `async with message_bus` 之内）完成 `subscribe`，才能不漏掉首帧。`run` 结束、上下文退出后订阅自动关闭，`async for` 自然结束。
- **思考过程**：若开启推理模式，思考文本在另一类事件（如 `REASONING_DELTA`）的 `data` 里，上例只打印最终正文；如需同时打印思考，可扩展 `if` 分支。

> 事件类型完整清单（含 `TEXT_BLOCK_DELTA` / `REASONING_DELTA` / `TOOL_CALL` 等）与 `data` 字段，见各事件文档与 `src/agentscope/event/_event.py`。
