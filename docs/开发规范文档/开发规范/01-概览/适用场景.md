# 适用场景：何时选用 L3 智能体框架

> 目标：判断一个业务场景该用 agentscope bocom（L3 智能体框架）还是行内 L2 智能体能力。agentscope bocom 即本规范所述的 L3 智能体框架——支持自主任务拆解、工具动态编排、多智能体协同。

## 选型总原则

当业务场景具备**任务流程复杂、存在动态分支、需要自主任务拆解**等特征时，推荐选用 L3 智能体开发框架；对于**规则明确、流程固定、执行路径可完整预定义**的标准化业务，选用行内 L2 智能体能力。

满足以下任意一类具体业务特征，建议采用 L3 智能体框架：

## 1. 任务需要自主拆解规划

业务目标明确，但具体执行步骤无法提前全部固化，智能体根据输入自行拆解子任务、动态调整执行顺序。

**典型案例**：客户综合业务咨询。客户提出一个复杂诉求（如贷款 + 账户变更 + 权益查询组合问题），没有固定流程，智能体自行拆解多个子任务，按需调用不同业务接口处理。

## 2. 工具链式复杂编排

业务需要灵活串联多个工具接口，工具调用顺序不固定，依据中间返回结果动态选择调用工具。

**典型案例**：对公客户风险初筛。先查询客户基本信息，根据返回结果动态判断是否需要进一步查询征信、交易流水、担保信息，工具调用顺序随中间结果变化。

## 3. 多智能体协同完成业务目标

框架支持**链式、团队主从、广播式、辩论交替**四种协同模式，各模式行内业务示例如下：

### （1）链式协同

上一个智能体输出作为下一个智能体输入，任务存在先后依赖。

**典型案例**：信贷申请材料预处理。第一个智能体做材料格式校验，第二个智能体提取关键字段，第三个智能体完成信息标准化整理，按流水线依次完成处理。

### （2）团队主从协同

Leader 智能体负责任务拆解、分配、结果汇总；多个 Worker 并行执行子任务。

**典型案例**：客户全方位画像分析。Leader 把任务拆分为交易行为分析、产品持有分析、风险特征分析，分发给不同 Worker 智能体并行计算，最后 Leader 汇总形成完整客户分析报告。

### （3）广播式协同

同一个请求同时发给所有智能体独立处理，最后对全部结果聚合汇总。

**典型案例**：贷前多方并行风险核查。同时分发至反欺诈智能体、合规智能体、信贷风险智能体，各个智能体独立输出风险点，再统一汇总全部风险提示。

### （4）辩论交替协同

多个智能体轮流交替接力，互相基于对方输出迭代完善结论。

**典型案例**：复杂业务方案研讨。分别配置业务、风控、合规三类智能体，轮流发表意见，互相指出漏洞，反复迭代打磨出兼顾业务可行性与风控合规的业务方案。
