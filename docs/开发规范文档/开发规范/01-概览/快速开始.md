# 快速开始

> 目标：走通「服务装配（create_app）→ 创建智能体 → 配置模型（ELLM 凭证）→ 配置工具与技能 → 对话 → 排查问题」的最小闭环。所有示例基于已启动的 agentscope bocom 服务，接口统一挂载在 **`/api`** 前缀下，且请求需携带身份头 **`X-User-ID`**。

## 0. 服务装配（create_app）

引入 agentscope bocom 包后，在你的工程中调用 `create_app` 一次性装配服务：传入存储、消息总线、工作区三个必填核心组件，开箱即得 12 组内置 REST 路由（`/agent`、`/credential`、`/session`、`/chat` 等）；企业能力全部经扩展点参数注入：

```python
from agentscope.app import create_app

# ── 03-工具对接包：注册行内工具，按会话装配（build_enterprise_tools 范式） ──
from bocomadp_tools import ToolRegistry

registry = ToolRegistry()
registry.register(query_internal_doc)            # 注册一个行内系统对接工具


async def build_agent_tools(user_id, agent_id, session_id):
    """返回当前会话可用的企业工具（签名与 create_app 约定一致）。"""
    return [query_internal_doc, submit_it_ticket]


# ── 04-技能对接包：注册行内技能 hub ──
from skill_hub_sdk import SkillHub, skill_router

# ── 05-记忆对接包：装配记忆中间件、注册记忆配置路由 ──
from bocomadp.memory import build_memory_middlewares, install_memory


async def build_agent_middlewares(user_id, agent_id, session_id):
    mws = await build_base_middlewares(user_id, agent_id, session_id)  # 已有中间件链
    mws.extend(await build_memory_middlewares(user_id, agent_id, session_id))
    return mws


app = create_app(
    # 必填核心组件
    storage=storage,                      # 持久化存储（智能体/凭证/会话/知识库元数据）
    message_bus=message_bus,              # 事件总线（会话事件发布订阅）
    workspace_manager=workspace_manager,  # 工作区后端（工具执行位置，如 K8s 沙箱）
    # 企业扩展点（可选）
    knowledge_base_manager=knowledge_base_manager,  # 知识库管理（RAG 知识召回）
    mcp_hubs=[GitHubMCPHub()],            # MCP 服务目录来源
    skill_hubs=[SkillHub()],              # 技能市场来源（04-技能）
    extra_agent_middlewares=build_agent_middlewares,  # 企业中间件注入点（05-记忆）
    extra_agent_tools=build_agent_tools,  # 企业工具注入点（03-工具）
)

app.include_router(skill_router)          # 技能安装/删除前端接口（04-技能）
install_memory(app)                       # 记忆配置路由（05-记忆）
```

| 参数 | 作用 | 详见 |
| ---- | ---- | ---- |
| `storage` | 持久化存储：智能体、凭证、会话、知识库元数据 | [08-部署·Agent服务](../02-agentscope官方参考文档/08-部署/Agent服务.md) |
| `message_bus` | 消息总线：会话事件的发布订阅（SSE 回放与实时推送） | [08-部署·Agent服务](../02-agentscope官方参考文档/08-部署/Agent服务.md) |
| `workspace_manager` | 工作区后端：工具在哪执行（K8s 沙箱等） | [07-工作区与沙箱](../02-agentscope官方参考文档/07-工作区与沙箱/概述.md) |
| `knowledge_base_manager` | 知识库管理（RAG 知识召回） | [03-知识召回](../03-自定义工具-mcp-cli/知识召回.md) |
| `mcp_hubs` | MCP 服务目录来源（或用 `McpRegistry` 注册） | [03-使用工具指南](../03-自定义工具-mcp-cli/使用工具指南.md) |
| `skill_hubs` | 技能市场来源，如 `SkillHub()`；挂 `skill_router` 获得前端安装/删除接口 | [04-使用技能指南](../04-技能/使用技能指南.md) |
| `extra_agent_middlewares` | 企业中间件注入点：回调返回中间件列表（如记忆中间件） | [05-记忆能力](../05-记忆/记忆能力.md) |
| `extra_agent_tools` | 企业工具注入点：回调返回工具列表（`build_enterprise_tools` 范式） | [03-使用工具指南](../03-自定义工具-mcp-cli/使用工具指南.md) |

装配完成后，在你的工程入口文件中启动（uvicorn，默认端口 `8000`，端口/自动重载按你的工程配置设置），`GET /healthz` 返回 200 即就绪。完整参数与内置路由清单见 [08-部署·Agent服务](../02-agentscope官方参考文档/08-部署/Agent服务.md)。

## 1. 前置条件

| 项 | 说明 |
| ---- | ---- |
| 服务已启动 | agentscope bocom 服务已运行（默认端口 8000），本文所有接口示例均基于该服务 |
| 身份头 | 所有接口携带 `X-User-ID: <你的工号>`（如 `zy`），缺失返回 401 |
| 模型凭证 | 按下方「第三步」准备好 ELLM 凭证（内网 ELLM 网关可达） |

**四个核心对象的关系**（后面会反复用到）：

```text
Agent（配置：是谁、怎么思考，创建后基本不变）
 ├── Session 1（会话：模型绑定 + 工作区 + 对话历史）
 │     └── Chat Run（一次回复执行）
 └── Session 2（同一 Agent 可开多个会话，绑不同模型）
```

先创建 Agent 拿到 `agent_id`，再创建凭证拿到 `credential_id`，最后创建 Session 时把二者绑定。

## 2. 创建智能体

### 方式 A：REST API 直接创建（推荐）

```bash
curl -X POST http://localhost:8000/api/agent/ \
  -H "X-User-ID: zy" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "文档整理助手",
    "system_prompt": "你是一名严谨的文档整理助手，擅长归纳与重排文档结构。"
  }'
# → {"agent_id": "agt_xxx"}
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `name` | 是 | 智能体显示名 |
| `system_prompt` | 否 | 身份与职责（默认 "You're a helpful assistant."） |
| `context_config` / `react_config` / `invite_config` | 否 | 上下文窗口策略 / ReAct 循环 / 团队邀请，均有默认值 |

用 `GET /api/agent/` 可列出已有智能体及其 `agent_id`。

### 方式 B：代码直接构造（开发期调试）

```python
from agentscope.agent import Agent
from bocomadp.credential import ELLMCredential
from bocomadp.providers.ellm_chat_model import EllmChatModel

cred = ELLMCredential(
    name="ellm-local",
    api_key="sk-any",                                   # 本地部署通常不校验
    base_url="http://host.docker.internal:8001/v1",     # ELLM OpenAI 兼容端点
)
model = EllmChatModel(credential=cred, model="deepseek-v4-flash")

agent = Agent(name="调试助手", system_prompt="...", model=model)
```

> 方式 B 适合本地快速验证；生产走方式 A + Session 绑定，模型与凭证在会话维度管理。

## 3. 配置模型（以 ELLM 凭证为例）

### 3.1 ELLM 是什么（30 秒）

**ELLM** 是行内自部署的企业大模型网关（模型由 DeepSeek-V4-Flash 等提供），对外暴露 **OpenAI 兼容端点（以 `/v1` 结尾）**。因此：

- 凭证：自定义 `ELLMCredential`（类型 `bocom_ellm_credential`），接入即注册；
- 模型：`EllmChatModel`，OpenAI 兼容调用，候选模型列表由 Redis 实时维护；
- 会话配置时 `chat_model_config.type` 填 `bocom_ellm_credential`、`model` 填如 `deepseek-v4-flash`。

### 3.2 创建 ELLM 凭证

**前端操作**：进入「凭证」管理页 → 新增凭证 → 选择类型 **ELLM**（表单由 `GET /api/credential/schemas` 动态渲染）→ 填写后保存。

**API 操作**：

```bash
curl -X POST http://localhost:8000/api/credential/ \
  -H "X-User-ID: zy" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "bocom_ellm_credential",
      "name": "内网 ELLM 主模型",
      "api_key": "sk-any",
      "base_url": "http://host.docker.internal:8001/v1",
      "organization": "bocom",
      "model": "deepseek-v4-flash"
    }
  }'
# → {"credential_id": "cred_xxx"}
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `type` | 是 | 固定 `bocom_ellm_credential`（凭证类型标识，决定用哪个模型类） |
| `name` | 否 | 显示名 |
| `api_key` | 是 | API key；**本地部署通常不校验、任意值即可**，生产环境由 key 刷新机制动态获取（见 3.4） |
| `base_url` | 否 | ELLM 的 OpenAI 兼容端点（`/v1` 结尾）；容器内访问宿主机服务用 `host.docker.internal` |
| `organization` | 否 | 组织 ID（OpenAI 兼容构造需要读取的字段） |
| `model` | 否 | 绑定的模型名（一凭证一模型）；留空则候选模型取全部（见 3.5） |
| `scene_code` / `api_key_url` / `apikey_expires_at` / `inject_think_tag` | 否 | 业务字段，原样存储；`inject_think_tag=true` 时流式回复首段文本前注入 `<think>` 标签 |

> 凭证按用户隔离（或被共享）。`GET /api/credential/` 列出可见凭证；`GET /api/model/credential?credential_id=<id>` 可查询该凭证绑定的候选模型。

### 3.3 把凭证绑定到会话

凭证只是「存好了 key」，要让智能体真正用它回答，需在**创建会话**时绑定：

```bash
# 1. 创建会话：绑定 agent + ELLM 凭证
curl -X POST http://localhost:8000/api/sessions/ \
  -H "X-User-ID: zy" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "agt_xxx",
    "name": "文档整理-生产环境",
    "chat_model_config": {
      "type": "bocom_ellm_credential",
      "credential_id": "cred_xxx",
      "model": "deepseek-v4-flash",
      "parameters": {"temperature": 0.7}
    }
  }'
# → {"session_id": "sess_yyy"}

# 2. 发第一条消息（fire-and-forget，事件走 SSE）
curl -X POST http://localhost:8000/api/chat/ \
  -H "X-User-ID: zy" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "agt_xxx",
    "session_id": "sess_yyy",
    "input": {
      "role": "user",
      "content": [{"type": "text", "text": "帮我梳理一下这份周报的结构"}]
    }
  }'
# → {"status": "started", "session_id": "sess_yyy"}

# 3. 前端通过 SSE 长连接接收回复事件
# GET /api/sessions/sess_yyy/stream?agent_id=agt_xxx
```

- `chat_model_config` **不配置则会话无法回复**（运行时会校验）；
- `fallback_chat_model_config` 可选：主模型失败时切换备用模型；
- `parameters` 支持 `temperature` / `top_p` / `max_tokens` / `enable_thinking` / `reasoning_effort` 等。

### 3.4 API key 生命周期（ELLM 特有机制）

行内 ELLM 网关的 key 会过期，平台内置 `EllmKeyRefreshMiddleware` 自动处理，**使用者无需手动换 key**：

```text
每次模型调用前：惰性刷新（key 未过期则复用）
     │
     ▼
网关返回 401(invalid_api_key / "API KEY不存在或已过期")
     │
     ▼
强制刷新一次并重试当前调用 → 成功则继续
     │
     ▼
刷新也失败 → 把该凭证标记为已过期 → 本次报错，下一次调用自动再刷
```

### 3.5 模型候选管理（`/api/ellm-models`）

ELLM 可调用的模型列表存于 Redis（`bocomadp:model:think_tag`），**增删改实时生效、无需重启**：

```bash
# 列出全部候选模型
curl -H "X-User-ID: zy" http://localhost:8000/api/ellm-models

# 新增一个模型（think_tag=1 表示流式回复注入 <think> 标签）
curl -X POST http://localhost:8000/api/ellm-models \
  -H "X-User-ID: zy" -H "Content-Type: application/json" \
  -d '{"model": "qwen3-235b-a22b", "think_tag": 0,
       "context_size": 1000000, "output_size": 384000}'

# 修改 / 删除
curl -X PUT    http://localhost:8000/api/ellm-models/qwen3-235b-a22b \
  -H "X-User-ID: zy" -H "Content-Type: application/json" \
  -d '{"think_tag": 1, "context_size": 1000000, "output_size": 384000}'
curl -X DELETE http://localhost:8000/api/ellm-models/qwen3-235b-a22b -H "X-User-ID: zy"
```

每个模型三个属性：`think_tag`（`<think>` 注入开关）、`context_size`（上下文 token 数）、`output_size`（最大输出 token 数）。Redis 不可用时候选列表自动降级读取本地 `_models/*.yaml`。

### 3.6 其他供应商

平台同时支持官方供应商（DashScope / OpenAI / DeepSeek / Gemini / Anthropic 等），配置方式一致：创建对应类型凭证 → 会话绑定时选对应 `type` 与 `model`。官方凭证类型说明见 [02-模型](../02-agentscope官方参考文档/04-模型/大语言模型.md)。

## 4. 配置工具

主包自带框架原生的工具机制（内置工具、`Toolkit` / `ToolRegistry`、MCP 接入，开箱即用）；独立发布的**工具包**（见 [03-自定义工具-mcp-cli](../03-自定义工具-mcp-cli/README.md)，可脱离平台单独安装）在其上提供行内系统的对接工具。三类来源**自动注入到每个会话**，无需逐个智能体手动装配：

| 来源 | 内容 | 配置开关 |
| ---- | ---- | ---- |
| 框架内置工具 | `Bash` / `Read` / `Write` / `Edit` / `Glob` / `Grep` / 计划模式四工具等 | `tools.enabled: true` |
| 企业自定义工具 | 行内系统对接（HR / Doc / ITSM / 企业信息查询等），`build_enterprise_tools` 按会话装配 | `tools.load_custom: true` |
| MCP 服务 | 复用生态 MCP server（Stdio / HTTP） | `mcp.enabled: true` |

**按智能体控制可用工具（最小权限）**——通过工具白名单接口：

```bash
# 仅保留 Bash 与 Read 两个工具（其余对该智能体不可见）
curl -X PUT http://localhost:8000/api/agents/agt_xxx/tools/Bash \
  -H "X-User-ID: zy" -H "Content-Type: application/json"
```

> 白名单为空 = 全部工具可用；非空 = 只保留名单内工具。删除同理：`DELETE /api/agents/{id}/tools/{name}`。

开发新的自定义工具 / 接入 MCP 的完整写法，见 [03-自定义工具-mcp-cli/README](../03-自定义工具-mcp-cli/README.md) 与 [使用工具指南](../03-自定义工具-mcp-cli/使用工具指南.md)。

## 5. 配置技能

技能 = 「教智能体一套做法」（SKILL.md），区别于工具（一个函数）。主包自带框架原生的技能机制；独立发布的**技能包** `skill_hub_sdk`（见 [04-使用技能指南](../04-技能/使用技能指南.md)）提供行内技能 hub 的对接，两种安装方式：

| 方式 | 做法 | 适用场景 |
| ---- | ---- | ---- |
| 前端接口 | 服务端注册 `SkillHub`/`BocomSkillHub` + 挂载 `skill_router`，前端浏览目录、点击安装 | Web UI 用户手动安装 |
| 代码直调 | `from skill_hub_sdk.services import install_skills`，在启动流程调用 | 启动预装 / 程序化初始化 |

最小可用示例（代码直调）：

```python
# 服务启动流程中调用
from skill_hub_sdk.services import install_skills

await install_skills(
    workspace_manager,
    user_id="zy",
    agent_id="agt_xxx",
    session_id="sess_yyy",
    skill_names=["global:write"],   # 命名空间:技能名
    # guwp_token="...",             # 可选；不传只能下载公共技能
)
```

**作用域**：技能装在「user_id + agent_id」维度，同一智能体的**所有会话共享**（agent 级共享 PVC），换新智能体才需重装。

完整接口清单、环境变量预装配置（`BOCOMADP_INSTALL_SKILLS`）与排障速查，见 [04-使用技能指南](../04-技能/使用技能指南.md)。

## 6. 排查问题

### 6.1 分层排查路径

```text
出问题先定位在哪一层：
1. 前端/请求层：接口返回码（401 缺 X-User-ID / 404 资源不属于你 / 409 会话已有回复在跑）
2. 服务日志：结构化日志携带 trace_id，访问日志（AccessLogMiddleware）记录每个请求
3. 模型层：ELLM 401 自动换 key 重试；仍失败看网关连通性（base_url 可达？）
4. 工具/沙箱层：工具在 K8s 沙箱执行，看 Pod 状态与 workspace 后端日志
5. 链路层：OTel 三层 span（invoke_agent → chat / execute_tool）定位卡在哪个环节
```

### 6.2 常用手段速查

| 手段 | 命令 / 入口 | 看什么 |
| ---- | ---- | ---- |
| 服务日志 | 服务运行日志 | `trace_id` 关联的报错上下文 |
| 会话事件回放 | `GET /api/sessions/{sid}/messages`、SSE 回放 | 卡在推理/工具/确认哪个环节 |
| 中断卡死的回复 | `POST /api/sessions/{sid}/interrupt` | 取消运行中或 HITL 暂停的回复 |
| Pod 状态 | `kubectl describe pod -n agentscope <pod>` | 沙箱是否拉起（Pending 常见：镜像拉取/PVC/资源） |
| tracing | 见 [06-tracing日志](../06-监控/tracing日志.md) | 模型调用耗时、工具执行结果 |
| 控制台调试 | `launch_console(agent)`（本地开发） | 终端直连智能体验证逻辑 |

### 6.3 常见问题速查表

| 现象 | 可能原因 | 处理 |
| ---- | ---- | ---- |
| 会话无法回复，报「未配置模型」 | 创建会话时没传 `chat_model_config` | `PATCH /api/sessions/{sid}` 或重建会话绑定凭证 |
| ELLM 返回 401 | key 已过期 | 平台自动刷新重试；仍失败检查网关可达性、`base_url` 是否以 `/v1` 结尾 |
| 凭证页模型下拉为空 | Redis 中无模型候选 / Redis 不可达 | 用 `/api/ellm-models` 添加；确认 Redis 连接 |
| 前端模型列表没出现 ELLM 的模型 | 凭证 `model` 字段与候选不一致 | 清空凭证 `model` 或改名为候选列表中的值 |
| 智能体调不到企业工具 | 服务配置未开 `tools.load_custom` / 被白名单过滤 | 检查 `tools.load_custom` 开关与 `/api/agents/{id}/tools` 白名单 |
| 工具调用卡住 | 沙箱 Pod 未拉起 / 工具在等人工确认 | 看 Pod 状态；权限系统触发人工确认时在 UI 确认 |
| 安装技能后没生效 | `agent_id` 不一致（技能按智能体维度共享） | 确认 `agent_id`；换新智能体需重装 |
| `POST /chat/` 返回 409 | 同一会话已有回复在跑 | 等待结束或 `POST /api/sessions/{sid}/interrupt` |
| 接口返回 401 | 缺 `X-User-ID` 头 | 所有请求携带 `X-User-ID` |
| 接口返回 404 | 资源不属于当前用户 / id 拼错 | 确认 id 归属与拼写 |
