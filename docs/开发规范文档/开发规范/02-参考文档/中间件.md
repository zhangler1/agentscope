# 中间件

> 目标：掌握中间件钩子体系，能不侵入智能体/模型代码地加入观测、预算、记忆、RAG 等横切能力。它取代了 1.0 的 hook 机制。

## 钩子总览

| 钩子                  | 时机                     | 典型用途                       |
| --------------------- | ------------------------ | ------------------------------ |
| `on_reply_start`      | 一轮回复开始             | 初始化轮次状态、注入首条提示   |
| `on_reasoning`        | 每个推理步骤             | 变换模型输入/输出、注入动态上下文 |
| `on_acting`           | 每个行动步骤（工具执行）  | 工具调用审计、参数改写         |
| `on_model_call`       | 每次底层模型调用         | 模型降级、请求重试、用量统计   |
| `on_compress_context` | 上下文压缩               | 定制摘要策略                   |
| `on_system_prompt`    | 系统提示组装             | 动态改写系统提示               |
| `list_tools`          | 工具列表构建             | 按条件注入/隐藏工具            |

中间件分三种实现类型：

- **Onion（洋葱）型**：包裹目标逻辑，前后各执行一段（计时、重试、预算）；
- **Transformer（变换）型**：纯函数式变换经过的数据（消息改写、输出过滤）；
- **Tool source 型**：通过 `list_tools` 向智能体注入工具（记忆、检索类中间件）。

## 装备与执行顺序

```python
agent = Agent(
    ...,
    middlewares=[
        TracingMiddleware(...),     # 最外层
        MyMiddleware(...),          # 中间层
        RAGMiddleware(...),         # 最内层
    ],
)
```

> **规则**：列表中**第一个中间件在最外层**。请求依次穿过 1→2→3，响应反向返回。

### ReplyBudgetControlMiddleware（token 预算）

每次模型调用后累计加权成本，超过预算立即优雅终止回复：

```python
from agentscope.middleware import ReplyBudgetControlMiddleware

middleware = ReplyBudgetControlMiddleware(
    max_budget=200_000,          # 加权 token 总预算
    input_token_weight=1.0,      # 输入 token 权重（缓存输入可设更低）
    output_token_weight=2.0,     # 输出 token 权重
)
```

计费公式：`cost = input_token_weight × input_tokens + output_token_weight × output_tokens`。该中间件无状态，跨智能体可复用同一实例。

## 自定义中间件

```python
from agentscope.middleware import AgentMiddlewareBase


class TimingMiddleware(AgentMiddlewareBase):
    """统计每轮回复耗时与模型调用次数。"""

    async def on_reply_start(self, agent, state, call_next):
        import time
        state.metadata = {**state.metadata, "_t0": time.monotonic(), "_calls": 0}
        result = await call_next(agent, state)
        elapsed = time.monotonic() - state.metadata["_t0"]
        print(f"本轮耗时 {elapsed:.1f}s，模型调用 {state.metadata['_calls']} 次")
        return result

    async def on_model_call(self, model, messages, config, call_next):
        state.metadata["_calls"] += 1
        return await call_next(model, messages, config)
```

一个展示事件流拦截能力的例子——「强制续跑一次」：首轮回复结束时吞掉 `ReplyEndEvent` 并注入继续提示，第二轮放行结束事件：

```python
class ContinueOnceMiddleware(AgentMiddlewareBase):
    def __init__(self) -> None:
        self.cur_iter = 0

    # 拦截 reply_stream：第一次 ReplyEndEvent 不放行，改为投递继续提示；
    # 第二次正常放行，让循环自然结束
    ...
```

> **警告**：拦截结束事件强行续跑时，务必同步维护智能体的迭代计数（如 `react_config.max_iterations` 对应的内部游标），否则可能突破最大迭代限制。

## 常见模式

| 模式         | 钩子              | 做法                                   |
| ------------ | ----------------- | -------------------------------------- |
| 限流         | `on_model_call`   | 在 `call_next` 前对调用频率把关        |
| 动态上下文   | `on_reasoning`    | 每轮注入最新业务数据（行情、工单状态） |
| 模型降级     | `on_model_call`   | 捕获失败后切换备用模型再调用           |
| 输出过滤     | `on_reasoning`    | 变换型：过滤/改写模型输出              |
| 工具白名单   | `list_tools`      | 按运行环境隐藏危险工具                 |
