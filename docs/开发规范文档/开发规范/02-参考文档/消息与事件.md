# 消息与事件

> 目标：掌握 `Msg` 与 `Event` 两类核心数据结构，能正确构造输入、消费事件流并重建消息。

消息（`Msg`）是**持久化的对话内容**，事件（`Event`）是**运行过程中的瞬时信号**。前端集成、human-in-the-loop、分布式事件流都建立在这两个抽象之上。

## Msg：统一的消息结构

`Msg` 继承自 Pydantic `BaseModel`，字段如下：

| 字段          | 类型                                                    | 说明                                  |
| ------------- | ------------------------------------------------------- | ------------------------------------- |
| `name`        | `str`                                                   | 消息发送者名称                        |
| `role`        | `Literal["system", "user", "assistant"]`                | 发送者角色，决定可用的内容块类型      |
| `content`     | `str \| list[Block]`                                    | 消息内容：纯文本或内容块列表          |
| `id`          | `str`                                                   | 消息唯一标识（自动生成）              |
| `created_at`  | `datetime`                                              | 消息创建时间                          |
| `finished_at` | `datetime`                                              | 消息完成时间                          |
| `usage`       | `Usage \| None`                                         | token 用量（prompt/completion/total） |
| `metadata`    | `dict`                                                  | 附加元数据                            |

常用方法：

| 方法                        | 说明                                            |
| --------------------------- | ----------------------------------------------- |
| `get_text_content()`        | 拼接并返回消息中所有文本内容，无文本时返回 `None` |
| `get_content_blocks(type)`  | 获取指定类型的内容块列表                        |
| `has_content_blocks(type)`  | 判断消息中是否存在指定类型的内容块              |
| `append_event(event)`       | 将智能体事件累积到消息中（见下文）              |

## 六种内容块

`content` 列表中的每个块通过 `type` 字段区分：

| 内容块            | type          | 核心字段                                       | 用途                          |
| ----------------- | ------------- | ---------------------------------------------- | ----------------------------- |
| `TextBlock`       | `text`        | `text: str`                                    | 普通文本                      |
| `DataBlock`       | `data`        | `media_type`、二进制数据或 URL                 | 图片/音频/视频等多模态数据    |
| `ThinkingBlock`   | `thinking`    | `thinking: str`                                | 模型思考过程（推理链）        |
| `ToolCallBlock`   | `tool_call`   | `name`、`input`、`id`、`state`、`suggested_rules` | 智能体发起的工具调用       |
| `ToolResultBlock` | `tool_result` | `tool_call_id`、`output`、`state`              | 工具执行结果                  |
| `HintBlock`       | `hint`        | `text: str`                                    | 提示块（系统引导、运行时注入、团队消息等） |

**角色与内容块的约束**（构造非法组合会校验失败）：

| 角色        | 允许的内容块                                  |
| ----------- | --------------------------------------------- |
| `system`    | `TextBlock`                                   |
| `user`      | `TextBlock`、`DataBlock`                      |
| `assistant` | `TextBlock`、`ThinkingBlock`、`ToolCallBlock`  |

`ToolResultBlock` 由框架在工具执行后写入上下文，开发者一般不手工构造。

## 消息工厂函数（推荐入口）

避免角色约束错误，用工厂函数创建消息：

```python
from agentscope.message import UserMsg, AssistantMsg, SystemMsg

msg = UserMsg("user", "帮我查一下天气")          # name, content
sys = SystemMsg("system", "你是一个天气助手")
```

**多实体对话**：群聊场景中 `name` 用于区分参与者，同名视为同一说话者：

```python
history = [
    UserMsg(name="Alice", content="大家好"),
    UserMsg(name="Bob", content="你好 Alice"),
]
```

需要让模型区分各发言者时，切换多智能体格式化器（各提供商均有对应实现）：

```python
from agentscope.model import DashScopeMultiAgentFormatter

model = DashScopeChatModel(
    ...,
    # 将消息渲染为 "Alice: ..." 风格
    formatter=DashScopeMultiAgentFormatter(),
)
```

## 构建复杂消息

```python
from agentscope.message import (
    AssistantMsg,
    DataBlock,
    TextBlock,
    ToolCallBlock,
    UserMsg,
)

# 多模态用户消息：文本 + 图片
user_msg = UserMsg("user", [
    TextBlock(text="这张图里有什么？"),
    DataBlock.image_from_path("chart.png"),   # 从本地文件构建图片块
])

# 带工具调用的助手消息
assistant_msg = AssistantMsg("Friday", [
    TextBlock(text="我来查询天气。"),
    ToolCallBlock(name="get_weather", input={"city": "北京"}, id="call_001"),
])
```

## 事件系统

`reply_stream` 产出事件，遵循 **start → delta → end** 生命周期（如文本依次产出 `TextStartEvent` → 若干 `TextDeltaEvent` → `TextEndEvent`）：

| 类别     | 事件（节选）                                                   | 说明                              |
| -------- | -------------------------------------------------------------- | --------------------------------- |
| 生命周期 | `ReplyStartEvent` / `ReplyEndEvent`                            | 一轮回复的开始与结束              |
| 文本     | `TextStartEvent` / `TextDeltaEvent` / `TextEndEvent`           | 回复文本的流式生成                |
| 思考     | `ThinkingStartEvent` / `ThinkingDeltaEvent` / `ThinkingEndEvent` | 模型思考过程                    |
| 工具调用 | `ToolCallStartEvent` / `ToolCallEndEvent`                      | 智能体发起工具调用                |
| 工具结果 | `ToolResultEvent`                                              | 单个工具执行完毕                  |
| 模型调用 | `ModelCallStartEvent` / `ModelCallEndEvent`                    | 底层模型调用（含 usage）          |
| 人工介入 | `RequireUserConfirmEvent` / `UserConfirmResultEvent`           | 工具确认请求与结果                |
| 人工介入 | `RequireExternalExecutionEvent` / `ExternalExecutionResultEvent` | 外部执行请求与结果              |
| 一次性   | `HintBlockEvent`、`CustomEvent`、`UserInterruptEvent`           | 提示块投递、自定义事件、用户中断  |

所有事件携带 `reply_id`（所属回复标识），用于归属区分与消息重建。

## 从事件流重建消息

`Msg.append_event()` 是事件流与消息模型之间的桥梁：

| 事件               | 对消息的影响                        |
| ------------------ | ----------------------------------- |
| `TextEndEvent`     | 追加一个 `TextBlock`                |
| `ThinkingEndEvent` | 追加一个 `ThinkingBlock`            |
| `ToolCallEndEvent` | 追加一个 `ToolCallBlock`            |
| `ToolResultEvent`  | 追加一个 `ToolResultBlock`          |
| `HintBlockEvent`   | 追加一个 `HintBlock`                |
| `ReplyEndEvent`    | 设置 `finished_at`、`usage` 并结束  |

```python
from agentscope.message import AssistantMsg

async def rebuild(agent, user_msg):
    """从事件流重建完整回复（自定义渲染逻辑时常用）。"""
    reply = None
    async for event in agent.reply_stream(user_msg):
        if reply is None:
            reply = AssistantMsg(agent.name, [])
            reply.id = event.reply_id
        reply.append_event(event)
    return reply
```

> **提示**：`agentscope.console.ConsoleRenderer` 内部就是用这一机制实现终端渲染的，见 [使用工具指南 · CLI 控制台](../03-工具-mcp-cli/使用工具指南.md#cli-控制台)。

## TypeScript 前端对接

```bash
pnpm install @agentscope-ai/agentscope
```

```typescript
import { AgentEvent, Msg } from "@agentscope-ai/agentscope";

for await (const event of stream) {
  if (event.type === "text_delta") {
    process.stdout.write(event.delta);
  }
}
```

SDK 类型与 Python 端 `Msg`/`Event` 对齐，前端无需重写协议。服务化对接（SSE、会话管理）见部署规范的 [对接微应用](../../部署规范/对接微应用.md)。
