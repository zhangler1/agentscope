# 启动准备

> 目标：把 BocomADP 服务在本地完整跑起来——装依赖、起数据库、配模型密钥、启动并验证。本文是"第一步"文档，回答「新环境里怎么把这套东西拉起来」；每个模块的详细用法见文末「与其他文档的关系」。

## 服务依赖

启动它之前，先确认基础设施：

| 组件 | 本地开发是否必需 | 用途 | 配置位置 |
| ---- | ---------------- | ---- | -------- |
| **OceanBase** | 必需（默认存储） | agent / session / 凭证 / 运行时配置的持久化（`AsyncSQLAlchemyStorage`） | `config.db` |
| **Redis** | K8s 沙箱模式必需；本地模式可选 | 消息总线（会话锁/回放/收件箱/唤醒）、并发控制（`RedisMessageBus`） | `config.redis` |
| **Qdrant** | 可选 | 知识库向量检索（示例默认 `:memory:`，重启即失） | `main.py` 中的 `QdrantStore` |
| **Docker / K8s** | 可选 | 沙箱工作区（工具执行隔离环境） | `ADP_K8S_ENABLED` 环境变量 |

启动模式由 `ADP_K8S_ENABLED` 决定：

| 模式 | 环境变量 | 工作区 | 消息总线 | 适用 |
| ---- | -------- | ------ | -------- | ---- |
| K8s 沙箱模式（默认） | `ADP_K8S_ENABLED=true` | 每智能体一个 Pod/PVC | `RedisMessageBus`（**需要 Redis**） | 生产 |
| 本地模式 | `ADP_K8S_ENABLED=false` | `LocalWorkspaceManager`（宿主目录） | `InMemoryMessageBus`（不需要 Redis） | 本地开发 / 测试 |

> **本地开发建议**：`ADP_K8S_ENABLED=false` + OceanBase + 可选 Redis。这样最少只需一个数据库就能跑起来。

## 第一步：环境准备

```bash
# 要求 Python ≥ 3.11
python --version

# 安装 agentscope（含 service / storage / workspace / rag 等全部 extras）
cd agentscope
uv pip install -e ".[full]"

# 数据库驱动：full 不包含具体驱动，按数据库选装
uv pip install aiomysql       # OceanBase（MySQL 协议兼容，推荐，本项目默认）
# uv pip install aiosqlite    # SQLite（零基础设施调试用）
```

## 第二步：配置数据库（重点）

### OceanBase：默认持久化后端

1. 启动一个 OceanBase 实例（本地没有可用实例时，`MODE=MINI` 为开发测试精简模式）：

```bash
docker run -d --name agentscope-ob \
  -p 2881:2881 \
  -e MODE=MINI \
  -e OB_TENANT_PASSWORD=agentscope \
  oceanbase/oceanbase-ce
```

> 启动初始化较慢（约 2~5 分钟），`docker logs -f agentscope-ob` 看到 `boot success!` 后再连；容器默认创建的业务租户名固定为 `test`，`OB_TENANT_PASSWORD` 即该租户 `root@test` 的密码。

2. 连接串格式：`mysql+aiomysql://<用户>:<密码>@<主机>:<端口>/<库名>`（OceanBase 兼容 MySQL 协议，端口默认 2881；用户需带租户，如 `root@test` 在 URL 中写作 `root%40test`）。

3. 在 `config.yaml` 的 `db:` 段配置（模板见 [配置项](../07-demo/配置项.md)）：

```yaml
db:
  url: "mysql+aiomysql://root%40test:agentscope@localhost:2881/test"
  create_tables: true        # dev/单机自动建表；多副本生产改用 alembic upgrade head
  pool_pre_ping: true        # 取连接前探测存活，服务端静默断连时自动重建
  pool_recycle: 1800         # 空闲连接 30 分钟回收，早于防火墙/NAT 空闲超时
```

| 配置项 | 默认 | 作用 |
| ------ | ---- | ---- |
| `url` | `mysql+aiomysql://root%40test:agentscope@localhost:2881/test` | SQLAlchemy async URL，支持 `mysql+aiomysql://`（OceanBase/MySQL）/ `postgresql+asyncpg://` / `sqlite+aiosqlite://` |
| `create_tables` | `true` | 启动时自动建表；生产多副本建议关掉，用 `alembic upgrade head` 避免迁移竞争 |
| `pool_pre_ping` | `true` | 取出连接前探测存活，服务端/网络静默断连时自动重建连接 |
| `pool_recycle` | `1800` | 空闲连接回收秒数，早于防火墙/NAT 空闲超时主动重建 |

> **不想装 OceanBase？** 把 `url` 换成 `sqlite+aiosqlite:///./agentscope.db` 即可零基础设施启动（单进程调试够用，多进程/生产必须换回 OceanBase）。

### Redis：消息总线（K8s 沙箱模式必需）

```bash
docker run -d --name agentscope-redis -p 6379:6379 redis:7
```

```yaml
redis:
  host: localhost
  port: 6379
  max_connections: 200      # Redis 连接池上限（压测/生产建议调大）
```

本地模式（`ADP_K8S_ENABLED=false`）不强制 Redis——消息总线退化为进程内 `InMemoryMessageBus`，但**并发控制、跨进程会话恢复、多副本部署**必须用 Redis。



## 第三步：准备配置与密钥

配置体系：**进程环境变量（`BOCOMADP_*`，嵌套字段用 `__` 分隔）> `.env` 文件 > `config.yaml`（含 `$VAR` / `${VAR}` 展开）> 代码默认值**。`config.yaml` 是唯一配置源。

```bash
cd examples/agent_service

# ① 环境变量模板 → 填写密钥（API Key 一律走这里，不进 config.yaml）
cp .env.example .env
# 编辑 .env：至少填 DEEPSEEK_API_KEY；其余按需（搜索类 URL 不配则对应工具报"未配置"）

# ② 配置主文件（仓库已带 config.yaml，直接用或从模板重建）
cp config.yaml.example config.yaml
```

常用部署期覆盖（也可直接写进 `.env`）：

```bash
BOCOMADP_SERVICE__HOST=0.0.0.0
BOCOMADP_SERVICE__PORT=8000
BOCOMADP_SERVICE__RELOAD=true          # 仅开发期开启自动重载
BOCOMADP_DB__URL=mysql+aiomysql://root%40test:agentscope@localhost:2881/test
BOCOMADP_REDIS__HOST=localhost
BOCOMADP_REDIS__PORT=6379
```

模型凭证两种来源（详见 [模型层](模型层.md)）：

1. **内置模型条目**：模型条目是代码内置的（`bocomadp/config/app_config.py` 的 `_builtin_model_entries`），敏感值从环境变量读取——主对话模型用 `DEEPSEEK_API_KEY`，多模态模型用 `ELLM_API_KEY` / `ELLM_BASE_URL`。启动时经 `ensure_default_credentials` 幂等刷入数据库为 default 用户凭证（模型名解析的默认回退），运行时可修改该记录实现全局切换，无需改配置文件；
2. **运行时创建**：调 `/api/credential` 接口创建凭证并绑定模型，多模型/按用户隔离时用。

## 第四步：启动服务

```bash
cd examples/agent_service

# 本地开发模式（推荐）：宿主目录工作区，不依赖 K8s
ADP_K8S_ENABLED=false python main.py
# 或（读 config.yaml 的 service.host/port）
# ADP_K8S_ENABLED=false uvicorn main:root_app --host 0.0.0.0 --port 8000 --reload

# 生产（默认）：K8s 沙箱工作区 + Redis 消息总线
# python main.py
```

启动成功后日志应包含：

```text
tools loaded: [...]
framework modules initialized: tools=.. middlewares=.. mcps=..
Starting BocomADP on 0.0.0.0:8000 ...
Uvicorn running on http://0.0.0.0:8000
```

启动时 lifespan 还会按序完成：自动建表（若 `create_tables`）→ 工具/中间件/MCP 注册表扫描 → 内置智能体（agent-creator）入库 → 默认凭证刷库 → 各业务补丁挂载。任一环节失败会打印异常并中断启动——最常见的失败点就是数据库连不上，见下文「常见问题」。

## 第五步：验证

```bash
# ① 健康检查（root 层，不经过 /api）
curl http://localhost:8000/healthz          # 存活
curl http://localhost:8000/readyz           # 就绪（依赖存储等资源）
curl http://localhost:8000/api/platform/health

# ② OpenAPI 在线文档（可交互调试）
# http://localhost:8000/docs
```

再走一条最小对话链路验证端到端（接口语义详见 [API接口文档](../../../examples/agent_service/docs/API接口文档.md)）：

```bash
# 创建智能体（模型由会话运行时凭证解析决定，不写在智能体配置里）
curl -X POST http://localhost:8000/api/agent/ \
  -H 'Content-Type: application/json' -H 'x-user-id: default' \
  -d '{"name":"demo","system_prompt":"你是一个助手"}'

# 创建 run + SSE 流式对话（thread_id 即 session_id，先创建会话或用任意 ID 懒建）
curl -N -X POST http://localhost:8000/api/threads/t1/runs/stream \
  -H 'Content-Type: application/json' -H 'x-user-id: default' \
  -d '{"agent_id":"demo","input":{"type":"human","content":"你好"}}'
```

Web UI（可选）：`cd examples/web_ui && pnpm install && pnpm dev`，API 端点填 `http://localhost:8000`。

## 常见问题速查

| 现象 | 原因与处理 |
| ---- | ---------- |
| 启动报 `connection refused` / `connection is closed` | OceanBase 未起（或仍在初始化）或连接串不对。先 `docker ps` 确认容器、`docker logs agentscope-ob` 看是否 `boot success!`，再核对 `config.db.url` 的账号/密码/库名/端口 |
| `ModuleNotFoundError: aiomysql` | full extra 不含数据库驱动，`uv pip install aiomysql` |
| 启动报 kubeconfig / K8s 相关错误 | 默认走 K8s 沙箱模式；本地开发设 `ADP_K8S_ENABLED=false` |
| Redis 未启动导致消息总线异常 | 本地模式不强制 Redis；若需多进程/并发控制，起 Redis 并在 `config.redis` 指对地址 |
| 对话返回 401 / 模型调用失败 | 检查 `.env` 的 `DEEPSEEK_API_KEY` 是否填写（内置模型条目从环境变量读 key，不再读 config.yaml 的 models 段）；凭证可在运行时经 `/api/credential` 重建 |
| 修改 config.yaml 后不生效 | `get_app_config()` 每次调用重建，配置支持热加载；但注册表/Redis 等**启动装配**用快照，改注册表开关需重启 |
| 数据要清空重来 | 删库重建（开发期）：`docker rm -f agentscope-ob` 后重跑第二步的 docker run |
