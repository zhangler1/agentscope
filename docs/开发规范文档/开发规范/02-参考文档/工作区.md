# 工作区（Workspace）

> 目标：让开发者理解工作区模块的作用与用法——它是什么、一个工作区对象怎么用、有哪些可配置项；以及什么情况下才需要服务端的 `WorkspaceManager`。

> **约定**：下文代码中的变量 `ws` 是 **Workspace** 的缩写（代码示例中的惯例变量名），指代当前操作的工作区对象，例如 `LocalWorkspace` / `DockerWorkspace` 的实例。

> 与 [沙箱](../06-安全/沙箱.md) 的分工：沙箱文档回答「选哪个后端、隔离粒度多大」（安全视角）；本文回答「这个模块提供什么、怎么调」（开发视角）。

## 为什么需要工作区

场景：你写了一个「代码库分析助手」——让智能体通读项目代码、运行测试、最后产出一份架构报告。

没有工作区时，智能体的 `Bash` / `Read` / `Write` 会落在「进程当前所在目录」，能碰到的范围不受控；长会话上下文压缩后，旧内容也没有固定去处。

有了工作区，一切都被圈定在一个目录里：

```text
你的项目目录（workdir）     ← 智能体所有的文件读写、命令执行都发生在这里
    ├── 智能体产出的文件（如 report.md）
    ├── sessions/          ← 上下文压缩后的历史、超大的工具结果（自动落盘）
    └── skills/            ← 你挂载的技能
```

## 工作区：一个对象，三件事

`WorkspaceBase`（所有工作区的统一抽象）把一个工作区对象拆成三块能力：

| 能力 | 具体内容 | 谁在用 |
| ---- | -------- | ------ |
| **Tools** | 六个内置工具（`Bash`/`Edit`/`Glob`/`Grep`/`Read`/`Write`，Windows 下 `Bash` 换 `PowerShell`）+ 已注册的 MCP | 智能体的 `Toolkit` |
| **Resources** | `skills/` 下的技能（`SKILL.md` + 目录） | 智能体的 `Toolkit` |
| **Offload** | 压缩出的旧上下文、超大工具结果的持久化落点 | 智能体上下文压缩时自动调用 |

接口是统一的，差异只在「执行环境」：`LocalWorkspace`（宿主目录，开发默认）、`DockerWorkspace`（容器）、`BubblewrapWorkspace`（轻量沙箱）、`E2BWorkspace` 等（云端）。**API 完全一致，换后端只改构造参数**，见下文「可配置项」。

## 最小场景：把工作区交给智能体

还是「代码库分析助手」，完整的最小可用代码：

```python
import asyncio

from agentscope.agent import Agent
from agentscope.message import UserMsg
from agentscope.tool import Toolkit
from agentscope.workspace import LocalWorkspace
from bocomadp.credential import ELLMCredential
from bocomadp.providers.ellm_chat_model import EllmChatModel


async def main() -> None:
    # ① 建工作区：把智能体的所有操作圈定在 ./my_project
    ws = LocalWorkspace(workdir="./my_project")
    await ws.initialize()   # 准备目录、恢复 .mcp 中的 MCP

    # ② 智能体（模型用行内 ELLM，见 [模型层](模型层.md)）
    agent = Agent(
        name="repo-analyzer",
        model=EllmChatModel(
            credential=ELLMCredential(
                api_key="...",                              # 本地部署通常不校验
                base_url="http://host.docker.internal:8001/v1",  # OpenAI 兼容端点，以 /v1 结尾
                organization="",
                # 无需填写 scene_code（场景码）等网关换 key 字段：
                # 本地直接调用时用不到，仅服务化接网关自动换 key 才需要（见 [模型层](模型层.md)）
            ),
            model="deepseek-v4-flash",   # 行内候选模型，也可用 Qwen3-235B-A22B 等
        ),
        toolkit=Toolkit(
            tools=await ws.list_tools(),   # 6 个文件/命令工具，全部绑定在 ws 内
        ),
        offloader=ws,   # ③ 上下文压缩/超限时自动卸载到 ws
    )

    # ④ 干活：读代码 → 跑测试 → 写 report.md（落在工作区内）
    reply = await agent.reply(
        UserMsg("user", "通读项目代码，运行测试，输出架构报告到 report.md"),
    )

    await ws.close()   # ⑤ 收尾：断开 MCP 等资源（目录保留）

asyncio.run(main())
```

这段代码背后发生了什么（原理）：

1. `ws.list_tools()` 返回的 6 个内置工具都绑定在 `ws` 的后端上——`Bash` 的当前目录是 `workdir`，`Read` / `Write` 只能读写工作区内的路径，智能体**碰不到工作区外的文件**；
2. `offloader=ws` 触发两件事：智能体的系统提示自动拼入工作区说明（让它知道「文件操作落在哪」）；上下文压缩或工具结果超限时自动调用 `ws.offload_context` / `ws.offload_tool_result` 落盘，旧内容随时可取回；
3. `ws.close()` 在本地模式主要是断开有状态 MCP 连接，`workdir` 目录本身保留，下次可继续用。

> **提示**：单机开发通常**一个工作区就够**——把 `workdir` 指到你的项目目录即可，不需要 `WorkspaceManager`（那是服务化的事，见下文）。

## 可配置项

开发者的工作区配置几乎都在构造时完成。本地模式只需决定 `workdir`：

| 构造参数 | 默认 | 作用 |
| -------- | ---- | ---- |
| `workdir` | 必填 | 工作区根目录：工具操作的边界 + 所有产物的落点 |
| `default_mcps` | `[]` | 首次启动播种的 MCP 列表（若 `<workdir>/.mcp` 已存在则忽略） |
| `skill_paths` | `[]` | 首次启动拷贝进 `skills/` 的技能目录 |
| `instructions` | 内置模板 | 系统提示片段，支持 `{workdir}` 占位符（一般不用改） |

换后端时的常用配置（完整选型见 [沙箱](../06-安全/沙箱.md)）：

```python
from agentscope.workspace import DockerWorkspace

ws = DockerWorkspace(
    base_image="python:3.11-slim",   # 容器镜像
    extra_pip=["pandas"],            # 预装依赖
    host_workdir="/data/project",    # 宿主挂载目录（不配则容器内不持久化）
)
```

## 工作区里有什么（目录布局）

```text
{workdir}/
├── .mcp          # 持久化的 MCP 注册（JSON 数组），重启自动恢复
├── data/         # 卸载的多模态文件（按内容哈希去重）
├── skills/       # 技能子目录（每个技能一个目录，含 SKILL.md）
└── sessions/     # 按会话分区的上下文与工具结果
    └── {session_id}/
        ├── context.jsonl              # offload_context 逐条追加
        └── tool_result-{id}.txt       # offload_tool_result 扁平文本
```

各目录由 `workdir` 自动派生，任何后端布局一致——排查「智能体把东西写哪了」看这里即可。

## 公共 API 速查

| 方法 | 什么时候用 |
| ---- | ---------- |
| `await ws.initialize()` | 准备后端（建目录/启容器/连沙箱），幂等；`async with ws:` 可自动进出 |
| `await ws.close()` / `ws.reset()` | 释放资源 / 清空为全新状态（**不**重新播种） |
| `await ws.list_tools()` | 取 6 个内置工具，塞进 `Toolkit` |
| `await ws.list_mcps()` / `add_mcp(c)` / `remove_mcp(name)` | 运行时动态增删 MCP（自动持久化到 `.mcp`） |
| `await ws.list_skills()` / `add_skill(path)` / `remove_skill(name)` | 挂载/卸载技能；`LocalWorkspace` 按内容哈希去重 |
| `await ws.offload_context(sid, msgs)` / `offload_tool_result(sid, r)` | 手动卸载（一般不用——Agent 压缩时自动调用） |
| `await ws.get_instructions()` | 工作区系统提示片段（`offloader=ws` 时自动拼入，无需手动） |
| `ws.get_backend()` | 直接拿底层后端做文件/命令操作（高级用法） |

## 服务端多租户：WorkspaceManager

> **单机开发者用不到这一节**——只有把智能体做成**多用户服务**（`create_app`）时，工作区数量随用户/智能体/会话增长、无法手工管理，才需要 `WorkspaceManagerBase`：

| 能力 | 说明 |
| ---- | ---- |
| 按需创建 + 缓存复用 | `get_workspace(user_id, agent_id, session_id, workspace_id=None)`：命中缓存直接返回，未命中才构建 |
| 空闲淘汰 | 进入 `async with` 后，后台 TTL 定期回收空闲工作区（`ttl` 默认 1 小时） |
| 统一回收 | `close_all()` 并行关闭全部缓存工作区（退出 `async with` 时自动调用） |

隔离粒度由 `IsolationPolicy` 决定（决定 `workspace_id` 怎么生成）：

| 策略 | 效果 |
| ---- | ---- |
| `PER_AGENT`（默认） | 同一智能体的会话共享工作区，跨会话保留文件 |
| `PER_USER` | 同一用户的所有智能体共享工作区 |
| `PER_SESSION` | 每个会话独立工作区（最干净，成本最高） |

接入方式一行：`create_app(workspace_manager=DockerWorkspaceManager(basedir=..., ttl=...))`，服务内部会自动经 `get_workspace` 绑定每个请求的执行环境，无需业务代码操心。

## 常见疑问速查

| 疑问 | 答案 |
| ---- | ---- |
| 智能体写出的文件在哪？ | `workdir` 下（如 `report.md`） |
| 上下文压缩后旧内容去哪了？ | `sessions/<id>/context.jsonl` + `data/` |
| 想限制智能体碰不到别的目录？ | 用独立的 `workdir`，或换 `DockerWorkspace` 容器隔离 |
| 想让多个会话共享产出文件？ | 复用同一个 `workdir`；服务化用 `PER_AGENT` |
| 想把卸载存到 S3？ | 实现 `Offloader` 协议，见 [上下文管理](上下文管理.md#上下文卸载offloader) |
| 沙箱内怎么装技能？ | `add_skill_archive(stream, fmt, dir_name)`（沙箱内展开，防路径穿越） |
