# 智能体

> 目标：掌握 `Agent` 的配置与运行、结构化输出、状态持久化、人机协作与中断——这是日常开发使用频率最高的一份参考。

`Agent` 是 AgentScope 的核心抽象：一个**无状态的推理-行动（ReAct）循环引擎**。所有状态显式存放在 `AgentState` 中，天然支持持久化、恢复与多进程部署。

## 核心接口与 ReAct 循环

| 方法                    | 说明                                                  |
| ----------------------- | ----------------------------------------------------- |
| `reply(inputs)`         | 运行完整 ReAct 循环，返回最终 `Msg`                   |
| `reply_stream(inputs)`  | 运行并产出事件流（`AsyncIterator[Event]`）            |
| `observe(inputs)`       | 只将输入注入上下文（不触发推理），用于旁听、预注入历史 |
| `compress_context(...)` | 手动触发上下文压缩（见 [上下文管理](上下文管理.md)）  |

ReAct 主循环：**推理（Reasoning）→ 行动（Acting）→ 观察（Observation）** 交替进行，直到模型产出不含工具调用的最终回复：

1. 模型基于当前上下文推理，可能产出思考、文本与工具调用；
2. 若有工具调用：经权限检查 →（必要时等待人工确认）→ 执行工具 → 结果以 `ToolResultBlock` 追加进上下文 → 回到 1；
3. 若无工具调用：该回复即为最终答案，循环结束。

## 构造参数总览

```python
Agent(
    name="Friday",
    system_prompt="...",                   # 身份与职责
    model=chat_model,                      # 必填：聊天模型实例
    toolkit=toolkit,                       # 工具箱（工具/技能/MCP）
    state=agent_state,                     # 显式状态（持久化/恢复）
    offloader=offloader,                   # 上下文卸载器
    middlewares=[...],                     # 智能体中间件
    model_config=ModelConfig(...),         # 模型调用参数覆盖
    context_config=ContextConfig(...),     # 上下文窗口策略
    injection_config=InjectionConfig(...), # 运行时状态注入
    react_config=ReActConfig(...),         # ReAct 循环行为（如最大迭代数）
    structured_schema=MyModel,             # 结构化输出 schema
    permission_context=PermissionContext(...),  # 权限配置
)
```

各配置项的完整说明见 [配置项速查](../07-demo/配置项.md)。

## 运行智能体

`reply` / `reply_stream` 的 `inputs` 支持四种类型：

| 输入类型            | 说明                                 |
| ------------------- | ------------------------------------ |
| `str`               | 等价于一条纯文本用户消息             |
| `Msg`               | 单条消息                             |
| `list[Msg]`         | 多条消息（多实体对话、预注入历史）   |
| `list[list[Msg]]`   | 多轮消息列表                         |

检查返回的 `Msg`：

| 字段/方法                        | 用途                                  |
| -------------------------------- | ------------------------------------- |
| `get_text_content()`             | 最终回复文本                          |
| `has_content_blocks("tool_call")` | 判断是否发起过工具调用               |
| `usage`                          | 本轮 token 消耗                       |
| `finished_at`                    | 完成时间（与 `created_at` 差即总耗时）|

`reply_stream` 支持 `yield_final_msg=True`，让事件流之后可直接拿到最终消息。

`observe` 不触发推理，适合：会话开始时预注入历史消息；把系统事件（如团队消息）写入上下文。

## 结构化输出

传入 Pydantic 模型 `structured_schema`，智能体获得内置工具 `GenerateStructuredOutput` 并自动校验产出：

```python
from pydantic import BaseModel

class WeatherReport(BaseModel):
    city: str
    temperature: float
    condition: str

agent = Agent(..., structured_schema=WeatherReport)

msg = await agent.reply("查询北京今天的天气并生成报告")
report = agent.structured_output   # WeatherReport 实例（校验通过后可用）
```

要点：

- 结构化输出以**工具调用**实现，模型在合适时机调用 `GenerateStructuredOutput` 提交结果；
- 校验失败时框架把错误反馈给模型重试（宽限迭代，默认若干轮），避免死循环；
- 校验通过前不产生最终回复；
- 结果存放在 `AgentState` 中，跨重启恢复会话后依然可用。

## 状态持久化

智能体状态（上下文、任务、结构化输出等）全部存放在 `AgentState`，可序列化为 JSON。配合 `RedisStorage` 实现跨会话持久化：

```python
import asyncio
import json

from agentscope.agent import Agent, AgentState
from agentscope.app.storage import RedisStorage

USER_ID = "u_001"
AGENT_ID = "a_friday"
SESSION_ID = "s_0001"


async def main() -> None:
    async with RedisStorage(host="localhost", port=6379) as storage:
        # 恢复：读取上一次保存的状态
        state = await storage.get_session(
            user_id=USER_ID, agent_id=AGENT_ID, session_id=SESSION_ID,
        )
        agent = Agent(
            name="Friday",
            model=model,
            state=AgentState.model_validate(state) if state else None,
        )

        msg = await agent.reply("继续我们刚才的话题")

        # 保存：upsert 整体覆盖
        await storage.upsert_session(
            user_id=USER_ID, agent_id=AGENT_ID, session_id=SESSION_ID,
            state=json.loads(agent.state.model_dump_json()),
        )

        # 增量更新运行时状态（不影响上下文主体）
        await storage.update_session_state(
            user_id=USER_ID, agent_id=AGENT_ID, session_id=SESSION_ID,
            key="finished_at", value=msg.finished_at.isoformat(),
        )


asyncio.run(main())
```

> **警告**：`upsert_session` 是**整体覆盖**语义——若只在会话结束时保存一次，中途崩溃会丢失全部进度。生产上建议每轮 `reply` 结束后立即保存。

## 人机协作（Human-in-the-Loop）

权限系统判定某工具调用需要确认时，`reply_stream` 产出 `RequireUserConfirmEvent` 并**暂停**，等待外部回传确认结果。三步处理：

```python
from agentscope.event import RequireUserConfirmEvent, UserConfirmResultEvent
from agentscope.permission import ConfirmResult

async for event in agent.reply_stream(UserMsg("user", "删除旧文件")):
    if isinstance(event, RequireUserConfirmEvent):
        # 第 1 步：读取待确认的工具调用（event.tool_calls，含 id/name/input）
        for tool in event.tool_calls:
            print(f"待确认: {tool.name}({tool.input})")

        # 第 2 步：收集用户决定，构建 ConfirmResult
        decision = ConfirmResult(
            confirmed=True,                     # 总体是否允许
            tool_call={event.tool_calls[0].id: True},   # 精确到单个调用 id
            rules=event.tool_calls[0].suggested_rules, # 同时接受建议规则
        )

        # 第 3 步：回传确认结果，智能体继续运行
        await agent.interrupt_queue.put(UserConfirmResultEvent(result=decision))
```

- `confirmed=False` 时本轮工具调用被拒绝，智能体收到拒绝反馈并调整策略；
- `rules` 可选：接受建议规则后，后续匹配相同规则的调用不再询问（控制台的 `a` 键即此行为）；
- 同一批待确认的工具调用只需回传一次结果。

### 外部执行工具

工具声明 `is_external_tool=True` 时，框架不执行它，而是把执行权交给人或外部系统——适合「智能体规划、人类执行」的场景（操作内部审批系统、线下设备等）：

```python
from agentscope.event import ExternalExecutionResultEvent, RequireExternalExecutionEvent
from agentscope.message import ToolResultBlock

async for event in agent.reply_stream(UserMsg("user", "帮我提交表单")):
    if isinstance(event, RequireExternalExecutionEvent):
        # event.tool_call：待执行的工具调用（id/name/input）
        result = do_it_manually(event.tool_call)

        await agent.interrupt_queue.put(
            ExternalExecutionResultEvent(
                tool_result=ToolResultBlock(
                    tool_call_id=event.tool_call.id,
                    output=result,
                )
            )
        )
```

## 中断智能体

两种中断方式，对应两种运行状态：

**运行中**（模型流式输出或工具执行中）——取消 asyncio 任务：

```python
task = asyncio.create_task(agent.reply(UserMsg("user", "写一篇长文")))
await asyncio.sleep(3)     # 中途取消
task.cancel()
```

**暂停中**（等待人工确认/外部执行时）——投递中断事件：

```python
from agentscope.event import UserInterruptEvent

await agent.interrupt_queue.put(
    UserInterruptEvent(reply_id=agent.state.reply_id)
)
```

中断是**干净展开**的：已完成的工具调用保留在上下文中，智能体状态一致，可接受下一次输入。
