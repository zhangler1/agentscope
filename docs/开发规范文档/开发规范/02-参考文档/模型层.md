# 模型层

> 目标：会配置和使用行内 ELLM 模型，包括凭证配置、模型调用、key 生命周期、模型候选管理与装配。

模型层采用**两层结构**：**凭证（Credential）** 负责密钥与端点，**模型类** 负责 API 调用与协议适配。行内凭证（`bocom_ellm_credential` 类型）对应模型类 `EllmChatModel`，二者在 `bocomadp` 中成套使用、可独立管理。

## 快速上手：接口注册凭证 → 发起对话

日常使用本项目，流程是**先用接口注册 ELLM 凭证，再发起对话**——全程不改代码、不重启服务。以下按顺序执行（假设服务已启动，默认端口 8000）：

**第 1 步：注册凭证**（`POST /api/credential/`，`data` 即凭证字段，见 [凭证字段](#凭证字段)；`base_url` 以 `/v1` 结尾）：

```bash
curl -X POST http://localhost:8000/api/credential/ \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "type": "bocom_ellm_credential",
      "name": "行内 ELLM 网关",
      "api_key": "...",
      "base_url": "http://host.docker.internal:8001/v1",
      "scene_code": "P2024146",
      "api_key_url": "http://eaip-ellm-1.bocomm.com/ELLM.ELLM-OMSERVICE.V-1.0/createSceneApiKey.do",
      "model": "deepseek-v4-flash"
    }
  }'
# → {"credential_id": "..."}（保存，更新/删除时用）
```

> `model` 可空（空时由会话 `chat_model_config.model` 指定，见第 2 步）；`scene_code` / `api_key_url` 是网关换 key 的依赖（见 [key 生命周期](#api-key-生命周期管理)）。

> 表单字段以接口为准：`GET /api/credential/schemas` 返回全部凭证类型的 JSON Schema，前端据此动态渲染创建表单；行内凭证的 `model` 字段带 enum（候选来自 Redis 模型表，即下拉框）。

**第 2 步：创建会话**（`POST /api/sessions/`，把第 1 步的凭证与模型绑定到会话；`chat_model_config` 字段：`type` = 凭证类型、`credential_id` = 凭证 id、`model` = 模型名、`parameters` = 模型参数）：

```bash
curl -X POST http://localhost:8000/api/sessions/ \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{
    "agent_id": "<agent_id>",
    "chat_model_config": {
      "type": "bocom_ellm_credential",
      "credential_id": "<上一步返回的 credential_id>",
      "model": "deepseek-v4-flash",
      "parameters": {"temperature": 0.3, "max_tokens": 8192}
    }
  }'
# → {"session_id": "..."}
```

> `agent_id` 为已创建的智能体（创建方式见 [智能体](智能体.md)）；`type` 与注册凭证的 `data.type` 一致。

**第 3 步：发起对话**（原生两段式：先订阅 SSE 事件流，再 `POST /api/chat/` 触发——对话异步执行，事件经 SSE 通道下发）：

```bash
# ① 订阅事件流（长连接：先回放缓冲历史，再接实时事件；建议先于触发建立）
curl -N "http://localhost:8000/api/sessions/{session_id}/stream?agent_id={agent_id}" \
  -H "X-User-ID: u_001"

# ② 触发对话（fire-and-forget，立即返回）
curl -X POST http://localhost:8000/api/chat/ \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{
    "agent_id": "<agent_id>",
    "session_id": "<上一步返回的 session_id>",
    "input": {"name": "user", "role": "user", "content": [{"type": "text", "text": "你好"}]}
  }'
# → {"status": "started", "session_id": "..."}
```

> 模型绑定在会话上（`chat_model_config`），对话请求**无需再带模型名**；`input` 为原生 Msg 结构（`name` / `role` / `content` 块数组）。换模型走 `PATCH /api/sessions/{session_id}` 更新 `chat_model_config` 即可。

对话时服务端按会话绑定的 `chat_model_config` 重建模型实例 → 中间件取新鲜 key（见 [key 生命周期](#api-key-生命周期管理)）→ 调用模型，流式增量经事件流透出前端。

**凭证管理**（同一组接口，框架内置）：

| 接口 | 说明 |
| ---- | ---- |
| `GET    /api/credential/`        | 列出当前用户可见凭证（共享凭证脱敏） |
| `POST   /api/credential/`        | 注册凭证 → 返回 `credential_id` |
| `PATCH  /api/credential/{id}`    | 更新凭证字段（如换 `base_url` / `model`） |
| `DELETE /api/credential/{id}`    | 删除凭证 |

### 凭证字段（接口注册用）

行内凭证类型为 `bocom_ellm_credential`，**平台已内置，无需开发**——注册时 `data` 支持以下字段：

| 字段               | 必填 | 说明                                                                                       |
| ------------------ | ---- | ------------------------------------------------------------------------------------------ |
| `api_key`          | 是   | ELLM 服务的 API key（本地部署通常不校验，任意值即可）                                      |
| `base_url`         | 否   | OpenAI 兼容端点（**以 `/v1` 结尾**）；容器内访问宿主机服务用 `host.docker.internal`        |
| `scene_code`       | 否   | 场景编码（业务字段，前端传入，原样存储）；网关换 key 用，见 [key 生命周期](#api-key-生命周期管理) |
| `api_key_url`      | 否   | API key 地址（业务字段）；网关换 key 用，见 [key 生命周期](#api-key-生命周期管理)          |
| `inject_think_tag` | 否   | 是否在流式响应首个非空文本 delta 前注入 `<think>` 标签（默认 `False`）                     |
| `apikey_expires_at`| 否   | API key 过期时间（Unix 秒）；**运行时自动维护**（自动刷新 key 时回写），无需手工配置，见 [key 生命周期](#api-key-生命周期管理) |
| `model`            | 否   | 绑定的模型名（可空，一凭证一模型）；为空时候选模型由 `list_models` 返回全部                |

> `model` 字段的候选来自 Redis 模型表（见 [模型候选管理](#模型候选管理)），前端凭证表单自动变为下拉框；凭证可跨用户共享（开放智能体交互）。

## EllmChatModel

`EllmChatModel`（`bocomadp/providers/ellm_chat_model.py`）继承框架 `ChatModelBase`，是 ELLM 网关的协议适配层。**不要直接用官方的 `OpenAIChatModel` 替代**——候选模型列表、`<think>` 注入、401 重试等行为都依赖本类。

### 构造参数

| 参数           | 类型                    | 说明                                                                                  |
| -------------- | ----------------------- | ------------------------------------------------------------------------------------- |
| `credential`   | 行内凭证，必填          | 凭证实例（接口注册后获取）                                                                  |
| `model`        | `str`                   | 模型名（如 `Qwen3-235B-A22B`、`deepseek-v4-flash`）                                   |
| `parameters`   | `Parameters \| None`    | `max_tokens` / `temperature` / `top_p`；`None` 时用默认参数                            |
| `stream`       | `bool`                  | 是否流式调用（默认 `True`）                                                           |
| `max_retries`  | `int`                   | 失败重试次数（默认 3）                                                                |
| `retry_delay`  | `float`                 | 重试间隔秒数（默认 1.0）                                                              |
| `context_size` | `int \| None`           | 上下文长度；`None` 时按模型名从 Redis 读取（无记录/不可用回退 65536）                  |
| `formatter`    | `FormatterBase \| None` | 消息格式化器；`None` 时用 `DeepSeekChatFormatter`                                      |
| `client_kwargs`| `dict \| None`          | 透传给 `openai.AsyncClient` 的额外参数（如 `timeout`、`default_headers`、`http_client`）|

### 直接调用示例（脱离智能体）

```python
from agentscope.message import TextBlock, UserMsg
from bocomadp.providers.ellm_chat_model import EllmChatModel

# credential 为已注册的凭证对象（接口注册见上；测试场景的代码构造见工作区文档）
model = EllmChatModel(
    credential=credential,
    model="deepseek-v4-flash",
    parameters={"max_tokens": 4096, "temperature": 0.7},
)

# 非流式：返回 ChatResponse（content 为文本/思考/工具调用块列表）
response = await model([UserMsg("user", "你好")])
print("\n".join(b.text for b in response.content if isinstance(b, TextBlock)))

# 流式（默认）：增量块 is_last=False，末块 is_last=True 为累积全文
async for chunk in model([UserMsg("user", "讲个故事")], stream=True):
    text = "".join(b.text for b in chunk.content if isinstance(b, TextBlock))
    if text:
        print(text, end="")
```

装配到智能体时与通用模型一致：`Agent(..., model=EllmChatModel(...))`。流式增量经框架事件流透出，前端逐字渲染无需关心协议细节。

### 协议行为须知（行内网关特点）

| 行为 | 说明 |
| ---- | ---- |
| 生成上限字段 | 网关只认 **`max_tokens`**，拒绝 `max_completion_tokens`——`EllmChatModel` 已固定用 `max_tokens` 发送 |
| `<think>` 注入 | 网关流式响应**不包裹** `<think>` 标签；`inject_think_tag=True` 时模型类在首个非空文本 delta 前注入。该开关的运行时优先级见 [key 生命周期](#api-key-生命周期管理) |
| 思考内容解析 | 网关的 `reasoning_content` 自动解析为 `ThinkingBlock`（思考过程），与正文分离 |
| 工具调用解析 | 流式 `tool_calls` 增量按 index 归并，产出 `ToolCallBlock` |
| usage | `input_tokens` / `output_tokens` / `cache_input_tokens`（网关 `prompt_cache_hit_tokens`），供计费与用量观测 |

### 模型候选

`EllmChatModel.list_models()` 返回候选 `ModelCard` 列表：**优先读 Redis 模型表**（`bocomadp:model:think_tag`），Redis 连接失败时降级读取 `bocomadp/providers/_models/*.yaml`，保证模型列表查询不因 Redis 抖动而不可用（见 [模型候选管理](#模型候选管理)）。

## 装配到服务

完整装配见 `examples/agent_service/main.py`，关键三步：

**第 1 步：导入即注册凭证**（自定义供应商随 import 注册）：

```python
from bocomadp.credential import ELLMCredential  # noqa: F401 — import 即注册自定义供应商
```

**第 2 步：模型候选入 Redis**（真源，日常通过接口写入，见 [模型候选管理](#模型候选管理)）：

```bash
curl -X POST http://localhost:8000/api/ellm-models \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4-flash", "think_tag": 1,
       "context_size": 1000000, "output_size": 384000}'
```

> `bocomadp/providers/_models/deepseek-v4-flash.yaml` **平时不参与**——运行时（`think_tag` / `context_size` / `output_size`）只读 Redis，读不到回退默认值。新增/修改模型写 Redis 即可。

**第 3 步：默认凭证幂等刷库**（`ensure_default_credentials`）：

```python
# main.py 启动时：内置模型条目作为 default 用户默认凭证幂等入库
# （default 用户凭证的单一数据源；失败仅告警不阻断启动）
await ensure_default_credentials(storage)
```

模型由框架按会话 `ChatModelConfig` 每轮重建。



## 模型候选管理

模型候选的**真源是 Redis**：

- **存储**：Redis Hash `bocomadp:model:think_tag`——field 即模型名，value 为 JSON：

```json
{"think_tag": 1, "context_size": 1000000, "output_size": 384000}
```

- `think_tag`：`1` 启用 `<think>` 注入（模型卡片 `output_types` 自动含 `application/x-thinking`），`0` 不启用；
- `context_size` / `output_size`：上下文与最大输出 token 数，默认 1000000 / 384000；
- **实时生效**：`list_models()` 每次查询都重新读 Redis，写入后前端候选与凭证表单立即更新，**无需重启服务**；
- **注意边界**：运行时（`inject_think_tag` 开关、`context_size`、`output_size`）只读 Redis，读不到即回退默认值（False / 65536 / 1000000 / 384000）。

### 数据来源

Redis 模型表**没有自动初始化**；该表的**唯一写入路径是管理接口**（人工/脚本调用，见下方管理路由）：

- 首次部署后模型表为空 → `list_models()` 返回空 → 凭证表单 `model` 下拉为空 → 需先 `POST /api/ellm-models` 写入候选模型；
- 已存在的模型 `POST` 返回 409——初始化脚本可先 `GET /api/ellm-models` 查询判存在，或直接复用接口幂等处理。

**管理路由**（`bocomadp/routers/ellm_models.py`）：

| 接口 | 说明 |
| ---- | ---- |
| `GET    /api/ellm-models`             | 列出全部模型 |
| `GET    /api/ellm-models/{model}`     | 查询单个模型 |
| `POST   /api/ellm-models`             | 新增模型（已存在 409） |
| `PUT    /api/ellm-models/{model}`     | 修改 think_tag / context_size / output_size / 模型名 |
| `DELETE /api/ellm-models/{model}`     | 删除模型（不存在 404） |

新增行内模型的标准流程：`POST /api/ellm-models` 写入 Redis → 前端凭证表单下拉自动出现该模型 → 创建/更新凭证绑定即可使用。yaml 无需同步维护（仅作 Redis 不可用时的列表兜底，可保留对齐内容）。



通用能力（所有模型类一致）：

- **模型级结构化输出**：`await model.generate_structured_output(schema, messages, instructions)` 直接返回校验后的 Pydantic 实例；智能体层的 `structured_schema` 基于此（见 [智能体 · 结构化输出](智能体.md#结构化输出)）；


## 行内模型使用检查清单

- [ ] 凭证已注册：`POST /api/credential/` 写入 `data.type = bocom_ellm_credential`（含 `scene_code`、`api_key_url`）
- [ ] `base_url` 以 `/v1` 结尾；容器内访问宿主机用 `host.docker.internal`
- [ ] key 生命周期配置：`ellm_key_refresh.refresh_ahead_secs` 设为 key 有效期 1/10 左右（120~180s）
- [ ] 模型候选已写入 Redis 模型表（`POST /api/ellm-models`，**首次部署必做**，无自动种子），前端下拉可见；
- [ ] 模型调用走 `EllmChatModel`（勿用官方 `OpenAIChatModel` 替代），`max_tokens` 由模型类处理
