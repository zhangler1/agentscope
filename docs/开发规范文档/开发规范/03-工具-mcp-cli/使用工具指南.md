# 使用工具指南

> 目标：会用内置工具、会写自定义工具、会接 MCP、会用 CLI 调试。

## 内置工具

| 工具     | 功能                                   | 权限要点                        |
| -------- | -------------------------------------- | ------------------------------- |
| `Bash`   | 执行 shell 命令                        | 多层安全分析，危险命令触发确认  |
| `Read`   | 读取文件（支持分页 `pages`）           | 只读快速通道                    |
| `Write`  | 写入/新建文件                          | 需先 Read 过目标文件（防盲写）  |
| `Edit`   | 精确替换文件内容（old/new 字符串对）   | 需先 Read 过目标文件            |
| `Glob`   | 按模式匹配查找文件                     | 只读                            |
| `Grep`   | 正则搜索文件内容                       | 只读                            |
| `TaskCreate` / `TaskGet` / `TaskList` / `TaskUpdate` | 计划模式四工具 | 状态注入，直接放行 |
| `GenerateStructuredOutput` | 结构化输出提交      | 直接放行                        |

### Bash 的安全分析

`Bash` 在执行前对命令做多轮静态分析（命令解析、只读分类、危险模式与路径检查、注入风险等），给出「直接放行 / 需要确认 / 直接拒绝」判定。可追加受保护路径：

```python
from agentscope.tool import Bash

bash = Bash(
    additional_dangerous_files=[
        "~/.aws/credentials",   # 追加受保护路径
    ],
)
```

### 文件工具的「先读后写」

`Write` / `Edit` 要求目标文件近期被 `Read` 过，防止智能体盲目覆盖未见过的内容——即使权限模式为 `ACCEPT_EDITS` 也依然生效。

> **注意**：Windows PowerShell 下部分命令的只读判定更保守，若干命令总是触发确认。

## 自定义工具（ToolBase）

```python
import httpx

from agentscope.tool import ToolBase


class WebSearch(ToolBase):
    """调用搜索 API 并返回结果摘要。"""

    name = "web_search"
    description = "搜索互联网，返回前 N 条结果的标题与摘要。"
    group = "basic"          # 所属工具组，默认 basic

    parameters = {
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "搜索关键词"},
            "max_results": {"type": "integer", "default": 5},
        },
        "required": ["query"],
    }

    async def call(self, query: str, max_results: int = 5) -> str:
        async with httpx.AsyncClient() as client:
            resp = await client.get(
                "https://api.example.com/search",
                params={"q": query, "limit": max_results},
            )
            results = resp.json()["results"]
        return "\n".join(f"- {r['title']}: {r['snippet']}" for r in results)
```

`ToolBase` 关键约定：

| 成员                   | 说明                                                          |
| ---------------------- | ------------------------------------------------------------- |
| `name` / `description` | 暴露给 LLM 的工具标识与描述                                   |
| `parameters`           | JSON Schema，约束调用参数                                     |
| `group`                | 所属工具组                                                    |
| `call(...)`            | **子类实现**的执行逻辑                                        |
| `__call__(...)`        | 框架统一调度入口（权限检查 → 执行 → 结果封装），**勿覆写**    |
| `check_permissions`    | 可选：自定义安全检查（见 [输入输出内容审核](../06-安全/输入输出内容审核.md)） |
| `check_read_only`      | 可选：声明工具是否只读（影响权限快速通道）                    |
| `is_external_tool`     | 声明为外部执行工具（见 [智能体 · 外部执行](../02-参考文档/智能体.md#外部执行工具)） |
| `bypass_immune`        | 安全检查免疫 bypass 模式                                      |

## 函数工具（FunctionTool）

无需写类，把普通异步函数快速包装为工具——适合原型与简单场景：

```python
from pydantic import BaseModel

from agentscope.tool import FunctionTool


class WeatherInput(BaseModel):
    city: str
    unit: str = "celsius"


async def get_weather(city: str, unit: str = "celsius") -> str:
    """查询指定城市的当前天气。"""
    return f"{city}: 25°C"


tool = FunctionTool(
    func=get_weather,
    input_schema=WeatherInput,   # Pydantic 模型自动转 JSON Schema
    group="basic",
)

toolkit = Toolkit(tools=[tool])
```

描述取自函数 docstring；也可传 dict 形式的 `input_schema` 覆盖自动推断。复杂状态与权限逻辑请用 `ToolBase` 类。

## 工具组与元工具 reset_tools

工具组让智能体按任务阶段切换可用工具集，减少工具过多导致的注意力稀释：

```python
from agentscope.tool import ToolGroup

database = ToolGroup(
    name="database",
    description="数据库查询与维护工具",
    tools=[QueryTool(), MigrateTool()],
)

deployment = ToolGroup(
    name="deployment",
    description="服务部署与回滚工具",
    tools=[DeployTool(), RollbackTool()],
)

toolkit = Toolkit(
    tools=[Bash(), Read(), Write()],   # basic 组（始终在线）
    groups=[database, deployment],
)
```

智能体运行时可调用元工具 `reset_tools(groups=[...])` 切换激活的工具组。

> **警告**：`reset_tools` 是**整体覆盖**语义——切换后只保留 `basic` 组与指定组，此前激活的其他组会被停用，而不是追加。

## MCP 接入

Toolkit 原生支持 MCP（Model Context Protocol）服务，注册后其工具自动对智能体可见：

```python
from agentscope.tool import HttpMCPConfig, StdioMCPConfig, Toolkit

toolkit = Toolkit(
    mcps=[
        # 有状态 · STDIO：子进程长连接
        StdioMCPConfig(
            command="npx",
            args=["-y", "@modelcontextprotocol/server-filesystem", "/data"],
        ),
        # 有状态 · HTTP：远程服务长连接
        HttpMCPConfig(
            url="https://mcp.example.com/mcp",
            headers={"Authorization": "Bearer <token>"},
        ),
    ],
)
```

- **按名筛选**：`StdioMCPConfig(..., enable_tools=["search", "fetch"])` 只导入指定工具；
- **命名空间**：MCP 工具以 `mcp__{server}__{tool}` 形式注册，避免跨服务重名冲突；
- **不经智能体直接调用**：

```python
from agentscope.tool import MCPClient

async with MCPClient(StdioMCPConfig(command=..., args=[...])) as client:
    tools = await client.list_tools()
    result = await tools[0].call({...})
```

无状态模式（短连接、每次调用独立）适合低频调用或服务端不支持长连接的场景。运行在沙箱内的 MCP 需通过工作区网关访问，见 [沙箱 · MCP 网关](../06-安全/沙箱.md#mcp-网关)。

## 工具中间件

拦截每一次工具调用，实现横切逻辑（日志、重试、审计、限流）。洋葱模型，`middlewares` 列表中**第一个在最外层**：

```python
import asyncio
import time

from agentscope.tool import Toolkit, ToolMiddlewareBase


class LoggingMiddleware(ToolMiddlewareBase):
    async def on_tool_call(self, tool, args, call_next):
        start = time.monotonic()
        result = await call_next(tool, args)      # 传递给下一层
        print(f"[{time.monotonic() - start:.2f}s] {tool.name}({args})")
        return result


class RetryMiddleware(ToolMiddlewareBase):
    def __init__(self, retries: int = 2) -> None:
        self.retries = retries

    async def on_tool_call(self, tool, args, call_next):
        for attempt in range(self.retries + 1):
            try:
                return await call_next(tool, args)
            except TransientError:
                if attempt == self.retries:
                    raise
                await asyncio.sleep(2**attempt)


toolkit = Toolkit(
    tools=[...],
    middlewares=[LoggingMiddleware(), RetryMiddleware()],  # 日志在外层
)
```

执行顺序：`Logging → Retry → 工具本体`。

## 执行后端切换

内置文件/命令工具的实际执行位置由**工作区（Workspace）**决定。切换后端只需换工作区实例，工具代码不变：

```python
from agentscope.agent import Agent
from agentscope.tool import Toolkit
from agentscope.workspace import DockerWorkspace

# 所有 Bash/Read/Write 调用都在容器内执行
workspace = DockerWorkspace(base_image="python:3.11-slim")
await workspace.initialize()

agent = Agent(
    name="Friday",
    model=model,
    toolkit=Toolkit(tools=workspace.get_backend()),   # 工作区提供的工具后端
    offloader=workspace,                              # 顺带接管上下文卸载
)
```

七种后端（Local/Bubblewrap/Docker/E2B/Daytona/K8s/OpenSandbox）的选型见 [沙箱](../06-安全/沙箱.md)。

## CLI 控制台

控制台模块提供两个接口，是开发期最趁手的调试工具：

| 接口                | 适用场景                                                     |
| ------------------- | ------------------------------------------------------------ |
| `launch_console`   | 与单个智能体交互式对话：内置输入循环、工具确认与中断处理      |
| `ConsoleRenderer`  | 嵌入自己的代码：只渲染事件流，输入与编排逻辑由调用方掌控     |

### launch_console

```python
import asyncio
import os

from agentscope.agent import Agent
from agentscope.console import launch_console
from agentscope.credential import DashScopeCredential
from agentscope.model import DashScopeChatModel
from agentscope.tool import Bash, Read, Toolkit, Write


async def main() -> None:
    agent = Agent(
        name="Friday",
        system_prompt="You're a helpful assistant named Friday.",
        model=DashScopeChatModel(
            credential=DashScopeCredential(
                api_key=os.environ["DASHSCOPE_API_KEY"],
            ),
            model="qwen3.7-max",
        ),
        toolkit=Toolkit(tools=[Bash(), Read(), Write()]),
    )
    await launch_console(agent)


asyncio.run(main())
```

交互行为：

| 环节     | 行为                                                              |
| -------- | ----------------------------------------------------------------- |
| 消息输入 | 以 `user>` 提示符读取输入，`exit`/`quit`/Ctrl+D 退出              |
| 流式渲染 | 回复文本与思考过程实时打印，工具调用与结果整块输出                |
| 工具确认 | `y` 允许一次；`a` 允许并接受建议权限规则（后续不再询问）；其余拒绝 |
| 中断     | 流式输出中 Ctrl+C 中断当前回复；确认提示处 Ctrl+C 终止本轮        |

参数：`agent`（必填）、`user_name`（默认 `user`）、`verbosity`（`quiet`/`default`/`debug`）、`max_tool_result_lines`（默认 20，`None` 不截断）。

> **注意**：`launch_console` 不含会话管理与持久化——状态随进程退出而消失。需要多用户、多会话、持久化时请用智能体服务，见 [CICD集成](../../部署规范/CICD集成.md)。

### ConsoleRenderer（被动渲染器）

```python
from agentscope.console import ConsoleRenderer

renderer = ConsoleRenderer()

async for event in agent.reply_stream(UserMsg("user", "你好！")):
    renderer.render(event)

final_msg = renderer.last_msg   # 渲染器按 reply_id 归属事件，累积出完整回复
```

多智能体顺序发言时可复用同一实例：

```python
msg = UserMsg("user", "写一段产品介绍")
for agent in [writer, reviewer]:
    async for event in agent.reply_stream(msg):
        renderer.render(event)
    msg = renderer.last_msg   # 上一个智能体的回复作为下一个的输入
```

渲染规则：回复文本与思考过程实时流式打印（思考以暗色显示）；工具调用与结果在结束事件到达时整块打印（并发结果不交错）；提示块以带边框面板展示；二进制数据以占位符显示（如 `[data: image/png, ~34KB]`）；每次模型调用后打印一行 token 用量。

verbosity 三档：`quiet`（仅回复文本与错误）、`default`（增加思考、工具、提示块、用量、确认提醒）、`debug`（再增加生命周期事件与工具结果元数据）。渲染器静默跳过未知事件类型，事件协议扩展不会破坏既有渲染。
