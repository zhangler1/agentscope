# 数据识别和脱敏

> 目标：保护敏感数据——凭证不落前端、危险路径不误写、共享资源可控可见。

## 敏感数据的三个暴露面

| 暴露面               | 风险                                         | 防护机制                       |
| -------------------- | -------------------------------------------- | ------------------------------ |
| API 密钥等凭证       | 泄露即被盗刷；前端 localStorage 被拖库       | 凭证脱敏（本页）               |
| 宿主敏感文件         | 智能体改写 `.env`/`.ssh` 导致失陷           | 危险路径保护（本页）           |
| 跨用户资源           | 租户数据越权访问                             | 默认拒绝共享（本页）           |

## 凭证管理：存储加密 + 响应脱敏

模型凭证（API Key）在智能体服务中的保护由框架自动完成：

- **存储加密**：`CredentialManager` 负责凭证 CRUD 与加密存储；
- **响应脱敏**：所有 API 响应中凭证只暴露 `type` 与 `name`，密钥值**永不回传**；
- **受信任路径解析**：原始密钥仅在**运行智能体时**于服务端受信任路径解析使用。

```bash
# 注册凭证（响应中的密钥被脱敏）
curl -X POST http://localhost:8000/credentials \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{"type": "dashscope", "name": "prod", "api_key": "sk-..."}'
# 响应：{"id": "cred_1", "type": "dashscope", "name": "prod"}  ← 无 api_key
```

> **警告**：切勿新增把已解析凭证回传客户端的端点；前端永远不需要也不应该拿到密钥值。

开发期的本地代码同样注意：密钥走**环境变量**而非硬编码：

```python
model = DashScopeChatModel(
    credential=DashScopeCredential(api_key=os.environ["DASHSCOPE_API_KEY"]),
    model="qwen3.7-max",
)
```

## 危险路径保护

权限系统内置的**数据识别**规则：以下路径的**写操作在任何模式下都会触发确认**（工具内置保护，`BYPASS` 也不放行）：

| 危险路径                     | 为什么危险                             |
| ---------------------------- | -------------------------------------- |
| `~/.bashrc` 等 shell 配置    | 可注入持久化后门命令                   |
| `~/.ssh/**`                  | SSH 密钥/配置被窃取或篡改              |
| `**/.env`                    | 环境变量文件常含密钥                   |
| `**/.git/**`                 | 篡改 git hooks 可执行任意代码          |
| 系统配置目录                 | 影响系统级行为                         |

配合工作目录规则形成分层防护：

- 工作区内（含 `additional_working_directories`）的读写走宽松通道；
- 超出工作区的路径默认触发确认；
- 危险路径**无条件确认**。

```python
from agentscope.permission import (
    AdditionalWorkingDirectory,
    PermissionContext,
    PermissionMode,
)

# 编辑自动放行 + 追加可信目录（注意：只放值得信任的目录）
agent = Agent(
    ...,
    permission_context=PermissionContext(
        mode=PermissionMode.ACCEPT_EDITS,
        additional_working_directories=[
            AdditionalWorkingDirectory(path="/data/shared-project"),
        ],
    ),
)
```

## 跨用户资源共享：默认拒绝

智能体服务按租户严格隔离，**默认策略 `DenyAllResourceAccessPolicy`——跨用户不共享任何资源**。

需要共享（如管理员统一配密钥供团队使用、发布调校好的智能体）时，实现资源访问策略：

### 两个接口

| 方法                                                        | 必需 | 说明                                                         |
| ----------------------------------------------------------- | ---- | ------------------------------------------------------------ |
| `list_accessible(viewer_id, kind, storage)`                 | 是   | 返回 viewer 可访问的 `ResourceRef`（**不含**其自有资源）     |
| `can_edit(viewer_id, kind, owner_id, resource_id, storage)` | 否   | 是否可修改；默认由 `list_accessible` 推导                    |

### 三步实现

```python
from agentscope.app.access import (
    ResourceAccessPolicyBase,
    ResourceKind,
    ResourcePermission,
    ResourceRef,
)
from agentscope.app.storage import StorageBase


class MyResourceAccessPolicy(ResourceAccessPolicyBase):
    """将用户 ID 映射为其可见的资源。"""

    async def list_accessible(
        self,
        viewer_id: str,
        kind: ResourceKind,
        storage: StorageBase,
    ) -> list[ResourceRef]:
        # 查询你的身份系统：viewer_id 能访问哪些 kind 资源
        # 注意：无需包含 viewer 自己拥有的资源
        ...


# 安装
app = create_app(
    ...,
    resource_access_policy=MyResourceAccessPolicy(),
)
```

### 描述共享内容

```python
# 把 Alice 的 API 凭证以只读共享给 Bob（Bob 可用但看不到密钥值）
ResourceRef(
    kind=ResourceKind.CREDENTIAL,
    owner_id="alice",
    resource_id="cred-openai-prod",
    permission=ResourcePermission.READ,
)

# 把 Alice 的智能体共享给 Bob 且可编辑
ResourceRef(
    kind=ResourceKind.AGENT,
    owner_id="alice",
    resource_id="agent-support-bot",
    permission=ResourcePermission.EDIT,
)
```

### 行为要点

- 共享凭证在所有响应中**脱敏**：访问者只能看到 `type` 与 `name`；
- 返回视图带按引用权限计算的 `editable` 标志，前端无需二次鉴权；`READ` 者尝试 `PATCH`/`DELETE` 得到 `403`，完全不可见的资源返回 `404`；
- 共享智能体共享的是**配置**（显示名、系统提示、context/ReAct 设置），**不含** workspace 内容——MCP 配置、skills、`MEMORY.md` 都在按用户隔离的工作区中，每个访问者从干净工作区起步。

## 开发清单

上线前对照检查：

| 检查项                                                   | 通过标准                                     |
| -------------------------------------------------------- | -------------------------------------------- |
| API 密钥无硬编码                                         | 全部走环境变量/凭证管理                      |
| 无任何端点回传密钥值                                     | 凭证响应仅含 `type`/`name`                   |
| 共享策略显式配置或确认默认拒绝                           | `resource_access_policy` 决策有记录          |
| `additional_working_directories` 只含可信目录            | 不含家目录、系统目录                         |
| 服务已替换占位鉴权                                       | 未使用默认 `X-User-ID` 信任逻辑              |

工具执行的门控与人工审核见 [输入/输出内容审核](输入输出内容审核.md)；执行环境隔离见 [沙箱](沙箱.md)。
