# 安全

> 目标：建立 AgentScope 的**纵深防御**认知——知道每一层防线挡住什么威胁，以及各层如何组合。

## 安全模型总览

智能体天然是"会执行动作的 LLM"，安全设计围绕**限制它能做什么**与**保护它接触的数据**展开：

```text
用户输入
   │
   ▼
┌─────────────────────────────┐
│ ① 权限门控（输入侧审核）     │  工具调用前的细粒度判定：ALLOW/ASK/DENY
├─────────────────────────────┤
│ ② HITL 人工确认              │  高危操作暂停，等人拍板
├─────────────────────────────┤
│ ③ 沙箱隔离（执行侧）         │  工具在受控环境内执行，炸不到宿主
├─────────────────────────────┤
│ ④ 数据识别与脱敏（输出侧）   │  凭证脱敏、危险路径保护、敏感信息不外泄
└─────────────────────────────┘
   │
   ▼
外部世界（文件系统 / 网络 / API）
```

## 各层速查

### ① 权限门控

三组件协同：**权限模式**（智能体整体自治度）× **权限规则**（按"工具 + 内容"粒度的 ALLOW/ASK/DENY）× **工具内置检查**（如 Bash 命令解析）。每次工具调用按六步决策链判定，DENY 规则任何模式都不可越过。

### ② HITL 人工确认

判定为 ASK 的调用会产出 `RequireUserConfirmEvent` 并**暂停**智能体，等待外部回传 `ConfirmResult`——这是权限系统在"人审"上的落点。

### ③ 沙箱隔离

工具不在宿主机直接执行，而是在**工作区**（Workspace）中运行：本地目录、Docker 容器、E2B 云沙箱……按需选择隔离强度。

### ④ 数据脱敏

凭证存储加密、响应脱敏（只回 `type` 与 `name`）；危险路径（`~/.ssh/**`、`**/.env` 等）写操作强制确认；共享资源默认全部拒绝。

## 组合建议

| 场景                     | 推荐组合                                                       |
| ------------------------ | -------------------------------------------------------------- |
| 本地开发调试             | `LocalWorkspace` + `DEFAULT` 模式（每次询问）                  |
| 内网生产、环境可控       | `DockerWorkspace` + `ACCEPT_EDITS` + DENY 护栏规则            |
| 对外服务、不可信代码执行 | 云沙箱（E2B/K8s）+ `EXPLORE`/`DONT_ASK` 白名单制 + 凭证脱敏   |
| 无人值守批处理           | `DONT_ASK` + `allow_rules` 白名单 + 沙箱兜底                   |

> **原则**：权限规则挡"不该做的"，沙箱挡"做了也炸不坏"，脱敏挡"看到了也拿不走"——三层各司其职，不要指望单层兜底。
