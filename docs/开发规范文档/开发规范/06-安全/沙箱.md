# 沙箱

> 目标：为工具执行选择正确的隔离环境——掌握七种工作区后端的选型、隔离粒度与资源挂载。

## 为什么需要沙箱

智能体的工具（Bash、文件读写、MCP 服务）直接操作真实环境。沙箱（工作区）决定**工具在哪执行、能碰到什么**：

- 本地开发：容器/目录隔离足够，方便调试；
- 生产/不可信代码：必须隔离文件系统与网络，故障半径可控；
- 多租户：每个用户/会话的执行环境互不可见。

## 七种工作区后端

| 工作区                 | 隔离方式               | 持久化               | 适用场景                     |
| ---------------------- | ---------------------- | -------------------- | ---------------------------- |
| `LocalWorkspace`       | 无（宿主文件系统）     | 宿主目录             | 本地开发、调试               |
| `BubblewrapWorkspace`  | bubblewrap 沙箱        | 宿主目录             | 单机轻量隔离（Linux）        |
| `DockerWorkspace`      | Docker 容器            | bind mount 宿主目录  | 单机生产、环境可控           |
| `E2BWorkspace`         | E2B 云沙箱             | 沙箱内（挂起/恢复）  | 云端托管、分布式             |
| `DaytonaWorkspace`     | Daytona 云沙箱         | 沙箱内（标签重挂）   | 云端托管                     |
| `K8sWorkspace`         | Kubernetes Pod         | PVC                  | 已有 K8s 集群                |
| `OpenSandboxWorkspace` | OpenSandbox            | 沙箱内（metadata）   | 自托管沙箱集群               |

> **警告**：`BubblewrapWorkspace` 只隔离文件系统，**不隔离网络命名空间**——需要网络隔离时用 Docker 及以上级别。

## 选型决策

```text
工具会执行不可信/高危操作吗？
├── 不会（纯本地开发调试）              → LocalWorkspace
├── 会，单机部署
│   ├── 只需文件系统隔离（Linux）       → BubblewrapWorkspace
│   └── 需要完整环境隔离                → DockerWorkspace
└── 会，云端/分布式
    ├── 用 E2B/Daytona 托管             → E2BWorkspace / DaytonaWorkspace
    └── 自有 K8s 集群                   → K8sWorkspace / OpenSandboxWorkspace
```

## 创建工作区

```python
# 本地
from agentscope.workspace import LocalWorkspace

ws = LocalWorkspace(
    workdir="/data/project",                  # 工作目录
    default_mcps=[StdioMCPConfig(...)],       # 所有会话共享的 MCP
    skill_paths=["./skills"],                 # 技能目录
)

# Docker
from agentscope.workspace import DockerWorkspace

ws = DockerWorkspace(
    base_image="python:3.11-slim",   # 基础镜像（按内容哈希缓存）
    workdir="/workspace",
    node_version="20",               # 内置 Node 主版本（npx 型 MCP 需要）
    extra_pip=["pandas", "httpx"],   # 预装依赖
)

# E2B 云沙箱
from agentscope.workspace import E2BWorkspace

ws = E2BWorkspace(
    template="base",                          # E2B 模板（自带所需运行时）
    api_key=os.environ.get("E2B_API_KEY"),    # 留空则读环境变量
)

# Kubernetes
from agentscope.workspace import K8sWorkspace

ws = K8sWorkspace(
    namespace="agentscope",
    image="python:3.11-slim",
    storage_size="1Gi",                       # PVC 兜底容量
)

await ws.initialize()   # 统一入口：准备底层后端
```

## 与智能体集成

```python
agent = Agent(
    name="Friday",
    model=model,
    toolkit=Toolkit(
        # 工作区提供的文件/命令工具（在对应后端内执行）
        tools=await ws.list_tools(),
        # 会话级 MCP：按 agent_id + session_id 隔离
        mcps=await ws.list_mcps(agent_id="a_001", session_id="s_0001"),
        # 技能：按 agent_id 隔离（该智能体的所有会话共享）
        skills_or_loaders=await ws.list_skills(agent_id="a_001"),
    ),
    offloader=ws,    # 上下文/工具结果卸载到工作区
)
```

## 隔离粒度

资源在工作区中的隔离规则：

| 资源类型 | 隔离粒度                 | 生命周期               |
| -------- | ------------------------ | ---------------------- |
| MCP      | `(agent_id, session_id)` | 会话结束即清理         |
| 技能     | `agent_id`               | 智能体生命周期内保留   |
| 文件     | 工作目录                 | 随工作区持久化策略     |

运行时动态管理：

```python
# 添加 MCP（立即建立连接，只影响该 agent+session）
await ws.add_mcp(
    agent_id="a_001",
    session_id="s_0001",
    config=HttpMCPConfig(url="https://mcp.example.com/mcp"),
)
await ws.remove_mcp(agent_id="a_001", session_id="s_0001", name="search")

# 技能：按 agent_id 挂载，跨会话保留
await ws.add_skill(agent_id="a_001", skill=local_skill)
await ws.remove_skill(agent_id="a_001", name="web-search")
```

## 生命周期

| 方法                     | 说明                                       |
| ------------------------ | ------------------------------------------ |
| `await ws.initialize()`  | 准备后端（启动容器/连接沙箱）               |
| `await ws.reset()`       | 清空工作目录与已挂载资源（保留工作区本身）  |
| `await ws.close()`       | 拆除后端、释放资源                          |
| `async with ws:`         | 进入自动 initialize，退出自动 close         |

> **提示**：服务化部署时不要手动管理工作区生命周期——用 [工作区管理器](../../部署规范/CICD集成.md)（`DockerWorkspaceManager` 等）按需创建、空闲淘汰、统一回收。

## MCP 网关：沙箱内服务的安全通道

运行在沙箱/容器**内部**的 MCP server（如需要容器内环境的 npx 服务）无法被宿主直接访问。工作区内置 **MCP 网关**解决这一问题：

- 沙箱内启动一个轻量 FastAPI 服务，代理沙箱内部各 MCP server；
- 宿主侧通过 `GatewayMCPClient` / `GatewayMCPTool` 适配器连接网关，如同访问本地 MCP；
- 网关通信带 **Bearer 令牌 + 实例随机数**双重防护，令牌仅存在于工作区内部，外部无法伪造；
- 沙箱**不需要发布任何端口**（不暴露攻击面），宿主通过工作区的受控通道访问。

开发者通常无需直接操作网关——`ws.list_mcps(...)` 返回的配置已自动包含网关接线。

## 沙箱不是全部

沙箱限制"执行在哪"，但**不判定"该不该执行"**——工具调用前的放行/拒绝由权限系统负责，见 [输入/输出内容审核](输入输出内容审核.md)；密钥等敏感数据的保护见 [数据识别和脱敏](数据识别和脱敏.md)。
