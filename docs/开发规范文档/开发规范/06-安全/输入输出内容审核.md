# 输入/输出内容审核

> 目标：控制"智能体能不能做这件事"——掌握权限门控（输入侧）、HITL 人工确认与输出侧审核的实现方式。

## 审核的三个环节

```text
输入侧：用户消息 →（可过滤/改写）
行为侧：工具调用 → 权限六步判定 → 放行 / 人审 / 拒绝
输出侧：模型产出 / 工具结果 →（可检查/改写后返回）
```

权限系统覆盖**行为侧**（最关键），输入/输出侧通过**中间件**扩展实现。

## 权限系统：工具调用的门控

### 三组件

| 组件             | 职责                                                         |
| ---------------- | ------------------------------------------------------------ |
| **权限模式**     | 智能体整体自治度（DEFAULT / ACCEPT_EDITS / EXPLORE / BYPASS / DONT_ASK） |
| **权限规则**     | 按「工具 + 内容」粒度声明 ALLOW / ASK / DENY                  |
| **工具内置检查** | 工具自身的安全分析（如 Bash 命令解析、文件路径保护）          |

### 六步决策流程（命中即停）

| 顺序 | 判定来源                 | 结果说明                                   |
| ---- | ------------------------ | ------------------------------------------ |
| ①    | **DENY 规则**命中         | 一律拒绝（所有模式均不可越过）             |
| ②    | **ASK 规则**命中          | 按当前模式决定：询问 / 放行 / 拒绝         |
| ③    | **只读快速通道**          | 工具声明只读且输入无风险 → 直接放行        |
| ④    | **工具内置检查**          | 工具 `check_permissions` 判定需要确认/拒绝 → 按模式处理 |
| ⑤    | **ALLOW 规则**命中        | 直接放行                                   |
| ⑥    | 兜底（无任何规则命中）    | 按模式默认行为处理                         |

### 五种模式对照

| 模式           | 定位                     | ASK 命中时 | 兜底行为                     |
| -------------- | ------------------------ | ---------- | ---------------------------- |
| `DEFAULT`      | 默认：人在回路           | 询问用户   | 询问用户                     |
| `ACCEPT_EDITS` | 自动接受编辑             | 询问用户   | 编辑类放行，其余询问         |
| `EXPLORE`      | 只读探索                 | 拒绝       | 只读放行，写操作拒绝         |
| `BYPASS`       | 全自动（护栏靠 DENY 规则）| 放行      | 放行（`bypass_immune` 工具除外） |
| `DONT_ASK`     | 无人值守（白名单制）     | 放行       | 拒绝（未列入 allow_rules 即拒绝） |

## 场景化配置

```python
from agentscope.permission import (
    PermissionContext,
    PermissionMode,
    PermissionRule,
)

# 场景一：只读探索（如代码调研智能体）
agent = Agent(
    ...,
    permission_context=PermissionContext(mode=PermissionMode.EXPLORE),
)

# 场景二：无人值守（Cron 任务、批处理）
agent = Agent(
    ...,
    permission_context=PermissionContext(
        mode=PermissionMode.DONT_ASK,
        allow_rules=[
            PermissionRule(tool_name="Bash", rule_content="npm run:*", behavior="allow"),
            PermissionRule(tool_name="Bash", rule_content="git *", behavior="allow"),
            PermissionRule(tool_name="Read", rule_content="**", behavior="allow"),
        ],
    ),
)

# 场景三：全自动但保留护栏
agent = Agent(
    ...,
    permission_context=PermissionContext(
        mode=PermissionMode.BYPASS,
        deny_rules=[
            PermissionRule(tool_name="Bash", rule_content="rm -rf*", behavior="deny"),
            PermissionRule(tool_name="Bash", rule_content="sudo *", behavior="deny"),
        ],
    ),
)
```

运行时切换模式（例如收到用户指令后收紧）：

```python
agent.state.permission_context.mode = PermissionMode.EXPLORE
```

### 规则匹配语法

`PermissionRule` 四字段：`tool_name`、`rule_content`（匹配内容）、`behavior`（allow/ask/deny）、`source`（系统预置或用户授予）。

```python
# Bash：前缀通配（"npm run:*" 匹配所有以 npm run: 开头的命令）
PermissionRule(tool_name="Bash", rule_content="npm run:*", behavior="allow")

# 文件工具：glob 模式（仅允许编辑 src 目录下的 Python 文件）
PermissionRule(tool_name="Edit", rule_content="src/**/*.py", behavior="allow")
```

规则的两条注入途径：

1. **静态配置**：构造 `PermissionContext` 时传入 `allow_rules` / `deny_rules` / `ask_rules`；
2. **运行时授予**：确认事件中携带 `rules`（`ConfirmResult(rules=suggested_rules)`），用户接受后生效。

## HITL：人工确认高危操作

权限判定需要确认时，`reply_stream` 产出 `RequireUserConfirmEvent` 并**暂停**，等待外部回传确认结果：

```python
from agentscope.event import RequireUserConfirmEvent, UserConfirmResultEvent
from agentscope.permission import ConfirmResult

async for event in agent.reply_stream(UserMsg("user", "删除旧文件")):
    if isinstance(event, RequireUserConfirmEvent):
        # 第 1 步：读取待确认的工具调用（event.tool_calls，含 id/name/input）
        for tool in event.tool_calls:
            print(f"待确认: {tool.name}({tool.input})")

        # 第 2 步：收集用户决定，构建 ConfirmResult
        decision = ConfirmResult(
            confirmed=True,        # 总体是否允许
            tool_call={            # 精确到单个工具调用 id
                event.tool_calls[0].id: True,
            },
            rules=event.tool_calls[0].suggested_rules,  # 同时接受建议的权限规则
        )

        # 第 3 步：回传确认结果，智能体继续运行
        await agent.interrupt_queue.put(
            UserConfirmResultEvent(result=decision)
        )
```

- `confirmed=False` 时本轮工具调用被拒绝，智能体会收到拒绝反馈并调整策略；
- `rules` 可选：接受建议规则后，后续匹配相同规则的调用不再询问；
- 同一批待确认的工具调用只需回传一次结果。

### 外部执行：人来做，智能体等结果

工具声明 `is_external_tool=True` 时，框架不执行它，而是把执行权交给人或外部系统：

```python
async for event in agent.reply_stream(UserMsg("user", "帮我提交表单")):
    if isinstance(event, RequireExternalExecutionEvent):
        # event.tool_call：待执行的工具调用（id/name/input）
        result = do_it_manually(event.tool_call)

        from agentscope.event import ExternalExecutionResultEvent
        from agentscope.message import ToolResultBlock

        await agent.interrupt_queue.put(
            ExternalExecutionResultEvent(
                tool_result=ToolResultBlock(
                    tool_call_id=event.tool_call.id,
                    output=result,
                )
            )
        )
```

适用于「智能体规划、人类执行」的场景，如操作内部审批系统、线下设备等。

## 自定义工具的安全检查

自定义工具可实现两层检查，参与决策流程的第 ③④ 步：

```python
from agentscope.permission import PermissionContext
from agentscope.tool import ToolBase


class DeployTool(ToolBase):
    name = "deploy"
    description = "部署服务到指定环境"
    bypass_immune = True      # 安全检查不受 BYPASS 模式豁免

    parameters = {...}

    def check_read_only(self, tool_input: dict) -> bool:
        # 返回 True 则可走只读快速通道
        return tool_input.get("dry_run", False) is True

    async def check_permissions(
        self,
        tool_input: dict,
        permission_context: PermissionContext,
    ):
        # 生产环境部署强制确认，其余交给规则链
        if tool_input.get("environment") == "production":
            return "ask"      # 需要 ASK 判定
        return None           # None 表示交回后续判定步骤
```

安全检查契约：

| 模式           | check_permissions 返回 ASK 时   | 返回 DENY 时 |
| -------------- | ------------------------------- | ------------ |
| `DEFAULT`      | 询问用户                        | 拒绝         |
| `ACCEPT_EDITS` | 询问用户                        | 拒绝         |
| `EXPLORE`      | 只读放行，写操作拒绝            | 拒绝         |
| `BYPASS`       | 放行（`bypass_immune=True` 时仍拒绝） | 拒绝  |
| `DONT_ASK`     | 按 allow_rules 匹配，未命中拒绝 | 拒绝         |

## 输入/输出侧的内容审核

权限系统管"工具调用"，对**文本内容**本身的审核（敏感词、合规、注入攻击检测）通过**中间件钩子**实现（见 [中间件](../02-参考文档/中间件.md)）：

| 钩子              | 审核对象             | 典型做法                                   |
| ----------------- | -------------------- | ------------------------------------------ |
| `on_reply_start`  | 用户输入             | 敏感词过滤、prompt 注入检测、改写或拒绝    |
| `on_reasoning`    | 模型产出（增量）     | 输出合规检查、流式内容拦截                 |
| `on_acting`       | 工具参数             | 二次校验参数（如 SQL 注入特征）            |

```python
class ContentModerationMiddleware(AgentMiddleware):
    async def on_reply_start(self, agent, state, inputs):
        # 输入侧：检测并处理违规内容
        if contains_sensitive_content(inputs):
            raise ValueError("输入包含违规内容")

    async def on_acting(self, agent, state, tool_call):
        # 行为侧：对特定工具的参数做二次校验
        if tool_call.name == "execute_sql" and has_injection(tool_call.input):
            return tool_call.model_copy(update={"input": blocked_result()})
```

> **提示**：公司如有现成的内容安全服务（如阿里云内容安全），在 `on_reasoning` 中调用其同步检测接口即可完成接入；流式场景可在 delta 累积到分句边界时送检。

执行环境隔离见 [沙箱](沙箱.md)；敏感数据保护见 [数据识别和脱敏](数据识别和脱敏.md)。
