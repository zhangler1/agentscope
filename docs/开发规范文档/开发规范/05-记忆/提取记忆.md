# 提取记忆

> 目标：掌握记忆如何被**写入与维护**——自动提取、显式写入、记忆整理与持久化布局。

## 提取机制对照

| 实现              | 写入方式                             | 触发时机                     |
| ----------------- | ------------------------------------ | ---------------------------- |
| `AgenticMemory`   | 小模型自动整理写入 Markdown          | 对话过程中异步执行           |
| `ReMe`            | 智能体工具写入 + 会话结束自动写回    | `agent_control`/`both` 模式  |
| `Mem0`            | `add_memory` 工具 + 自动提取         | 智能体主动 / 框架自动        |

三种实现的检索路径见 [检索记忆](检索记忆.md)。

## AgenticMemory：自动提取与整理

记忆的**写入与整理由 `memory_model` 驱动**——这是一个独立于主模型的"记忆小管家"，建议配置便宜的小模型：

```python
from agentscope.middleware import AgenticMemoryMiddleware

memory = AgenticMemoryMiddleware(
    memory_model=DashScopeChatModel(
        credential=DashScopeCredential(api_key=...),
        model="qwen3-flash",   # 整理与检索打分都用它，成本远低于主模型
    ),
    memory_dir=workspace.workdir / "agentscope" / "memory",
)
```

### 记忆目录布局

```text
agentscope/memory/
├── MEMORY.md          # 索引：各条记忆的标题与摘要
└── notes/             # 每条记忆一个 Markdown 文件（含 frontmatter 元数据）
```

- **MEMORY.md**：索引文件，记忆小模型维护，用于快速定位；
- **notes/**：每条记忆独立成文，含 frontmatter 元数据（标题、时间、标签等），语义检索在索引上打分、按需读取原文。

### 三种部署环境的持久化

`memory_dir` 指向的位置决定记忆的持久化方式：

| 环境          | `memory_dir` 位置           | 持久化效果               |
| ------------- | --------------------------- | ------------------------ |
| 本地开发      | `LocalWorkspace` 内目录     | 目录即持久化             |
| Docker        | bind mount 目录             | 宿主机目录保留           |
| E2B 沙箱      | 沙箱内目录                  | 随沙箱持久化             |

> **提示**：把 `memory_dir` 放在**工作区内**（如示例中的 `workspace.workdir / "agentscope" / "memory"`），记忆即可随工作区一起持久化与恢复。

## ReMe：自主写入与会话回写

`ReMeMiddleware` 在 `agent_control` 或 `both` 模式下，智能体获得记忆写入工具，可**主动**把重要信息存入记忆；会话结束时，智能体的记忆体会**自动写回**（auto memory），无需人工干预。

```python
memory = ReMeMiddleware(
    credentials=...,
    mode="both",              # 自动注入 + 智能体可主动读写
    session_scoped=False,     # True：记忆仅本会话可见（临时记忆）
)
```

> **注意**：`session_scoped=True` 适合"只在本轮任务内记住"的场景（如多步任务的中间结论）；跨会话的用户画像务必保持默认 `False`。

## Mem0：add_memory 工具

装配 `Mem0Middleware` 后，智能体获得两个工具：

| 工具            | 方向     | 说明                       |
| --------------- | -------- | -------------------------- |
| `search_memory` | 读（检索） | 按语义检索历史记忆         |
| `add_memory`    | 写（提取） | 把重要信息写入长期记忆     |

配合框架自动提取的双模式使用——智能体判断信息值得长期保留时主动调用 `add_memory`，无需在系统提示中额外约定。

## 自定义记忆提取逻辑

长期记忆实现本质上是**智能体中间件**（见 [中间件](../02-参考文档/中间件.md)）。若三种内置实现都不满足需求（如提取规则强业务化、需要写入自建存储），可参考中间件钩子体系自行实现：

- `on_reply_start`：检索并注入相关记忆；
- `on_reasoning` / 轮次结束钩子：从对话中提取候选记忆；
- 结合 `AgentState` 或外部存储持久化。

```python
class MyMemoryMiddleware(AgentMiddleware):
    async def on_reply_start(self, agent, state, inputs):
        # 1. 检索：按需召回记忆并注入上下文
        ...
    # 2. 提取：在轮次结束后把新信息写入你的存储
```

## 常见问题

| 问题                               | 处理建议                                                       |
| ---------------------------------- | -------------------------------------------------------------- |
| 记忆越积越多，检索变慢             | 定期整理/归档旧记忆；AgenticMemory 由 memory_model 自动整理索引 |
| 记住了不该记的敏感信息             | 在提取侧过滤（自定义中间件），或定期清理 notes/                |
| 主模型成本异常升高                 | 检查是否误用主模型做 memory_model——应换用便宜的小模型          |
| 多会话并发写同一 memory_dir        | 为每个用户/会话规划独立记忆目录，配合工作区隔离（见 [沙箱](../06-安全/沙箱.md)） |
