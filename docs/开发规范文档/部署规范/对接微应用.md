# 对接微应用

> 目标：让你的微应用（Web 前端、小程序、IM 机器人）用上智能体服务——掌握 REST API、SSE 事件流、鉴权与 IM 渠道接入。

## 四种对接方式

| 方式               | 适合                                     | 说明                                   |
| ------------------ | ---------------------------------------- | -------------------------------------- |
| 官方 Web UI        | 快速验证、内部工具                       | 仓库自带 `examples/web_ui`，pnpm 起动  |
| REST + SSE         | 自研前端 / 任意语言后端                  | 本文主体                               |
| TypeScript SDK     | 前端直接消费事件流                       | 消息与事件类型定义，见开发规范·消息与事件 |
| IM 渠道            | 飞书/钉钉/Discord 机器人                 | 无需前端开发                           |

## REST API 总览

主要端点分组：

| 分组         | 端点（节选）                                            |
| ------------ | ------------------------------------------------------- |
| 凭证与模型   | `POST/GET/DELETE /credentials`、`GET /models`           |
| 智能体       | `POST/GET/PATCH/DELETE /agents`                          |
| 会话         | `POST /agents/{id}/sessions`、`GET /sessions/{id}`       |
| 对话         | `POST /sessions/{id}/chat`、`GET /sessions/{id}/stream`（SSE）、`POST /sessions/{id}/interrupt` |
| 调度         | `POST/GET/DELETE /schedules`                             |
| 工作区       | `/sessions/{id}/workspaces/*`（MCP、技能挂载）           |
| 知识库       | `/knowledge_bases/*`                                     |
| 渠道         | `/channels/*`                                            |

## 典型对接流程（五步）

```bash
# 1. 注册凭证（响应中的密钥被脱敏，见 开发规范/06-安全/数据识别和脱敏.md）
curl -X POST http://localhost:8000/credentials \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{"type": "dashscope", "name": "prod", "api_key": "sk-..."}'

# 2. 创建智能体
curl -X POST http://localhost:8000/agents \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{"name": "Friday", "system_prompt": "You are Friday...", "model": {"credential_id": "cred_1", "model": "qwen3.7-max"}}'

# 3. 创建会话
curl -X POST http://localhost:8000/agents/a_001/sessions \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" -d '{}'

# 4. 触发对话（异步，立即返回）
curl -X POST http://localhost:8000/sessions/s_0001/chat \
  -H "X-User-ID: u_001" -H "Content-Type: application/json" \
  -d '{"message": "帮我分析这份数据"}'

# 5. 订阅事件流（SSE，先回放缓冲历史再接实时事件）
curl -N http://localhost:8000/sessions/s_0001/stream -H "X-User-ID: u_001"

# 中断正在运行的回复
curl -X POST http://localhost:8000/sessions/s_0001/interrupt -H "X-User-ID: u_001"
```

### SSE 事件流要点

- `POST /chat` **异步返回**，进度全靠订阅 `/stream`；
- 订阅时**先收到缓冲的历史事件，再接实时事件**——多 tab 同开、断线重连都能恢复到同一状态；
- 事件类型（文本增量、思考过程、工具调用、工具结果、确认请求等）与开发规范 [消息与事件](../开发规范/02-参考文档/消息与事件.md) 一致——前端渲染逻辑可参考其"从事件流重建消息"一节；
- 权限判定需要确认时，事件流中会出现**确认请求**，前端弹窗收集用户决定后回传（HITL 协议见开发规范·智能体）。

## 自定义鉴权

服务默认信任 `X-User-ID` header（占位依赖），生产必须替换为你的鉴权体系：

```python
from fastapi import HTTPException, Request

from agentscope.app import create_app
from agentscope.app.deps import get_user_id   # 占位依赖


async def jwt_user_id(request: Request) -> str:
    token = request.headers.get("Authorization", "").removeprefix("Bearer ")
    payload = verify_jwt(token)               # 你的 JWT 校验
    if payload is None:
        raise HTTPException(status_code=401, detail="invalid token")
    return payload["sub"]


app = create_app(storage=..., message_bus=..., workspace_manager=...)
app.dependency_overrides[get_user_id] = jwt_user_id
```

微应用侧：登录后持有 JWT，每个请求带 `Authorization: Bearer <token>` 即可，服务自动把 JWT subject 当作 `user_id` 完成租户隔离。

## 协议适配（AG-UI / A2A）

若微应用使用标准协议（而非原生事件流），通过**协议层中间件**转换：

```python
app = create_app(
    ...,
    extra_middlewares=[AGUIProtocolMiddleware(...)],   # 内置参考实现
)
```

自定义协议实现 `ProtocolMiddlewareBase` 处理 SSE 事件转换，经 `extra_middlewares` 注入。

不写前端，直接让智能体入驻 IM：

| 平台          | 类型标识    | 接入方式             | 状态          |
| ------------- | ----------- | -------------------- | ------------- |
| 飞书（Lark）  | `feishu`    | WebSocket 长连接     | 可用          |
| Discord       | `discord`   | Gateway WebSocket    | 可用          |
| 钉钉          | `dingtalk`  | Stream 模式长连接    | 可用          |
| 企业微信      | `wecom`     | 应用回调             | Coming soon   |

### 启用

```python
app = create_app(
    ...,
    channels=[FeishuChannel, DingTalkChannel, DiscordChannel],
)
```

依赖：`pip install "agentscope[channel]"`。渠道实例经 `/channels` 接口管理（创建、启用/停用、状态查询）。

### 会话路由

路由决定「消息交给哪个智能体、进入哪个会话」——一组**按序匹配、首条命中即停**的规则，最后一条兜底规则保证任何消息都有确定去向：

| 字段            | 说明                                                                 | 默认       |
| --------------- | -------------------------------------------------------------------- | ---------- |
| `match_key`     | 匹配哪个字段：`chat_id`、`user_id`、`metadata` 里的键（如 `chat_type`） | `chat_id`  |
| `match_value`   | 精确匹配值，或 `"*"`（兜底）                                         | `"*"`      |
| `agent_id`      | 命中后交给哪个智能体                                                 | 必填       |
| `session_scope` | 命中后进入哪个会话                                                   | `per_chat` |

```json
{
  "bindings": [
    {
      "match_key": "chat_id",
      "match_value": "oc_product_team",
      "agent_id": "product-expert",
      "session_scope": "per_chat"
    },
    {
      "match_key": "chat_id",
      "match_value": "*",
      "agent_id": "friday",
      "session_scope": "per_chat"
    }
  ]
}
```

保存配置时的三项校验：

- 必须有且仅有一条兜底规则（`match_value` 为 `"*"`）；
- 兜底规则必须在最后，否则其后的规则永远不会命中；
- 不允许重复的 `(match_key, match_value)` 组合。

> **提示**：配置前调用 `GET /channels/{id}/chat_ids` 列出机器人已知的聊天及其 `chat_id`，直接复制即可。

### 平台侧配置要点

各渠道均有三开关：`only_at_reply`（群聊仅被 @ 时回复）、`show_thinking`（展示思考过程）、`show_tool_process`（展示工具调用过程）。

- **飞书**：企业自建应用 + 机器人能力 + 事件订阅选**长连接**（无需公网回调），订阅 `im.message.receive_v1`；
- **钉钉**：企业内部应用，消息接收模式设为 **Stream 模式**；审批卡片可自定义（模板导入后**必须发布**）；
- **Discord**：创建 Bot 后务必开启 **MESSAGE CONTENT INTENT**（不开启收不到消息内容）。

对话内的**工具审批**在 IM 中以交互式卡片呈现，用户点击批准/拒绝即恢复运行——渠道框架从不信任卡片回传内容，权威状态以会话状态为准，天然分布式安全。
