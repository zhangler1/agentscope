# AgentScope 框架源码研读指引

按"先总览、后分层、再跟主线"的思路组织。

## 一、先建立全局认知

AgentScope 2.0 是一款面向生产的企业级智能体框架，核心设计理念是"以事件驱动的大模型推理-行动循环（ReAct）为中心，消息（Msg）为统一数据载体，模型/工具/中间件均可插拔"。

先读三样东西建立心智模型：

1. `README_zh.md` —— 了解五大卖点：事件系统、权限系统、多租户服务、工作区/沙箱、中间件系统
2. `记录/一次问答的全流程.md` —— 仓库内已有的一次完整问答链路梳理，是最好的"主线地图"
3. `记录/理解user-agent-session.md` —— 理解服务层的租户/会话模型

## 三、推荐研读路线（六步递进）

### 第 0 步：跑起来（30 分钟）

研读 `examples/agent_service/main.py` 与 `examples/agent_service/config.yaml`。理解一个 Agent 服务如何组装：模型 + 工具 + 中间件 + Agent 配置。`tests/` 下每个 `*_test.py` 也是极佳的最小用例文档。

### 第 1 步：数据载体（message → event）

- `message/_base.py`：Msg 是唯一消息类，content 由 **ContentBlock 列表**组成——这是全框架最重要的数据抽象
- `message/_block.py`：Text/Thinking/ToolCall/ToolResult/Data 各类 block
- `event/_event.py`：从 EventType 枚举入手，理解流式输出如何被拆成 START/DELTA/END 事件

### 第 2 步：模型抽象（model + formatter 对照读）

- `model/_base.py`：ChatModelBase 的输入输出契约（输入 Msg 列表，输出 ChatResponse）
- **对照读一对**：`model/_openai_chat/_model.py` ↔ `formatter/_openai_formatter.py`，理解"模型负责调用、formatter 负责格式转换"的分工
- `model/_model_response.py`：统一响应类型（ChatResponse/StructuredResponse/FinishedReason）

### 第 3 步：工具与权限（tool + permission + mcp）

- `tool/_base.py`：工具协议（`__call__` 契约 + ParamsBase + ToolMiddlewareBase 洋葱模型）
- `tool/_toolkit.py`：工具注册与注入
- `permission/_engine.py`：权限决策引擎（本项目权限最小化实践的核心）
- `mcp/_mcp_client.py`：外部 MCP 工具如何桥接进 Tool 协议

### 第 4 步：Agent 核心循环（重头戏）

- `agent/_agent.py`：约 3300 行，**不要从头读到尾**。先读 `__init__` 与 `reply` 方法，画出一轮 ReAct 循环：组装 Msg → 调用模型 → 解析 ToolCall → 权限检查 → 执行工具 → 回填 ToolResult → 再进模型，直至结束
- `agent/_config.py`：ReActConfig/ContextConfig/InjectionConfig 等配置模型
- `state/_state.py`：AgentState 与 ReplyContext
- 结合 `event/_event.py` 的事件类型，理解循环每一步向外发射什么事件

### 第 5 步：扩展机制（middleware + workspace + rag）

- `middleware/_base.py`：中间件钩子协议
- `middleware/_budget.py`：最简中间件，适合入门
- `workspace/_base.py`：沙箱抽象，再选一个后端深读（本项目重点在 `_k8s/`）
- `middleware/_rag.py` 与 `middleware/_longterm_memory/`：知识注入类扩展

### 第 6 步：服务层（app，按需研读）

- `app/_app.py` 与 `app/_lifespan.py`：服务组装与生命周期
- `app/_router/chat.py` → `app/_service/chat.py`：**一次请求的入口主线**，配合 `记录/一次问答的全流程.md` 阅读
- `app/message_bus/_base.py`：消息总线（Redis/内存两种实现），Agent 间通信与事件分发
- `app/storage/_base.py`：存储抽象（本项目已去 Redis 化、走 SQL）

## 四、研读技巧

1. **以事件流为线索**：框架一切可见行为都是事件。在 `_agent.py` 里搜 `yield`/AgentEvent，事件序列 = 执行轨迹
2. **对照 formatter 与 model 成对读**：新增一个模型供应商 = 写一个 model 子类 + 一个 formatter 子类 + 一张 ModelCard
3. **利用 tests 当文档**：`tests/agent_basic_test.py`、`tests/toolkit_test.py`、`tests/permission_engine_test.py` 等测试文件展示了每个模块的最小可运行用法
4. **仓库内现成业务文档**：`记录/` 目录下 5 篇文档（一次问答全流程、chat 接口 custom_params、知识库上传与图片处理、自定义企业知识库搜索、user-agent-session 理解）是前人研读成果，优先消化

## 五、常见研读目标 → 最短路径

| 想搞懂什么 | 直接读 |
|---|---|
| 一条消息怎么贯穿全系统 | message/_base.py → agent/_agent.py 的 reply → event/_event.py |
| 如何接一个新模型 | model/_base.py + formatter/_formatter_base.py + 任一家实现 |
| 如何加一个新工具 | tool/_base.py + tool/_toolkit.py + tool/_builtin/read.py（最简参考） |
| 工具权限如何生效 | tool/_base.py 中 PermissionContext → permission/_engine.py |
| 多智能体/多租户如何工作 | app/message_bus/_base.py + app/_router/chat.py + app/_service/chat.py |
| 沙箱如何隔离执行 | workspace/_base.py → workspace/_k8s/（本项目重点后端） |
| 知识库/RAG 链路 | app/rag/ + middleware/_rag.py + 记录/知识库文件上传与图片处理逻辑.md |
